# 技能点数换算系统（Skill Points System）

> 版本：v1.0  
> 设计目标：为自定义技能系统提供一个通用、"公平"的数值平衡框架。用统一的"点数(P)"衡量技能强度，再通过公式将点数映射为 SP/MP/CD 消耗。

## 1. 核心概念

### 1.1 什么是"点数"（P）

点数是一个抽象强度单位。技能的每一项正面属性（射程、倍率、多段、控制、位移等）都会增加点数；每一项限制（近距离、高消耗等不在此处考虑）本质上是点数转消耗时的"折扣"。

**点数的意义**：一个 10P 的技能，无论是什么类型，理论上应该和另一个 10P 的技能有相近的"战斗力贡献"。

### 1.2 三层体系

```
[技能属性] → 求和 → [点数 P] → 映射公式 → [SP / MP / CD 消耗]
   ↑                      ↑                      ↑
 模板底价             非线性求和            资源维度拆分
 属性增量             衰减曲线              CD-点数置换
 效果标签
```

### 1.3 非线性原则

**点数不是线性叠加的**。一个同时拥有"高倍率 + 远射程 + 控制 + 多段"的技能，总点数应该大于各属性单独定价之和。这是为了防止极端技能（把所有强力属性堆在一起，然后靠天文数字的CD来平衡 → 实际上变成"一发出胜负"）。

## 2. 点数计算总公式

```
P_total = (P_template + Σ P_attr) × (1 + synergy_tax)
```

其中：

- **P_template**：技能模板底价（见 §3）
- **P_attr**：每项属性的增量点数（见 §4、§5），**每个 P_attr 先经过自身的衰减函数 f(x) 再累加**
- **synergy_tax**：协同惩罚系数，当技能同时拥有多个"高强度标签"时触发

### 2.1 协同惩罚（synergy_tax）

如果一个技能同时满足以下条件中的 ≥2 项，触发协同惩罚：

| 高强度标签 | 判定条件                               |
| ---------- | -------------------------------------- |
| 高倍率     | damageRatio ≥ 1.5                      |
| 远程       | range ≥ 6 或 bulletRange ≥ 6           |
| 强控制     | stunDuration ≥ 2 或 freezeDuration ≥ 2 |
| 多段       | multiShot ≥ 3                          |
| 大范围     | aoeRadius ≥ 2                          |

```
synergy_tax = 0.00  (0-1 个标签)
synergy_tax = 0.12  (2 个标签)
synergy_tax = 0.25  (3 个标签)
synergy_tax = 0.45  (4+ 个标签)
```

**举例**：一个技能同时有 damageRatio=1.6、range=7、stunDuration=2，标签数=3，synergy_tax=0.25。原始点数=20P，最终=20×1.25=25P。

## 3. 技能模板底价

每种技能类型有一个基础点数，反映该类型的"固有优势"。

| 类型                | 底价      | 说明                                 |
| ------------------- | --------- | ------------------------------------ |
| `melee`             | **3.0 P** | 近战，受距离限制大，需要走到敌人面前 |
| `projectile`        | **5.0 P** | 飞行弹幕，远程安全输出               |
| `dash`              | **4.5 P** | 位移+伤害，兼具攻防价值              |
| `targeted_aoe`      | **7.0 P** | 必中AOE，无视弹幕碰撞，最强模板      |
| `teleport_backstab` | **6.0 P** | 瞬移到身后，功能性极强               |

### 3.1 类型设计哲学

- **melee 最便宜**：因为受距离限制最大，且弹幕等级通常较低容易被拦截。
- **targeted_aoe 最贵**：全图锁定 + 范围伤害 + 无视弹幕碰撞，是该游戏最强势的技能形态。
- **projectile 中间价**：远程但可被高等级弹幕拦截。
- **dash 中等**：位移价值 + 可穿越敌人。
- **teleport_backstab 较贵**：强制换位 + 自动转向，配合背刺有极高爆发潜力。

## 4. 技能属性定价

### 4.1 伤害倍率（damageRatio / backstabRatio）

伤害倍率是最核心的强度维度。采用**平方增长**而非线性，防止"堆倍率"成为最优解。

```
P_damage = k × r²
```

其中 `r` 取 `damageRatio` 和 `backstabRatio` 中的较大值（取 max，因为玩家总是会尽量触发更强的那一侧）。

| 倍率 r | P_damage (k=5) | 说明                           |
| ------ | -------------- | ------------------------------ |
| 0.0    | 0              | 纯功能技能（如魔法盾、暗影步） |
| 0.3    | 0.45           | 毒瓶的直伤部分                 |
| 0.5    | 1.25           | 连续射击单发                   |
| 0.8    | 3.2            | 精准射击 / 突击盾              |
| 1.0    | 5.0            | 旋风斩                         |
| 1.2    | 7.2            | 箭雨 / 匕首攻击(正面)          |
| 1.6    | 12.8           | 重击                           |
| 2.0    | 20.0           | 背刺匕首(背面) 理论值          |
| 2.4    | 28.8           | 背刺匕首 backstabRatio         |

**为什么用平方？**  
线性增长下，r=2.0 是 r=1.0 的两倍价格，但实际战斗中一发 2.0 倍率几乎等于秒杀（对法师=38伤，法师只有70HP），两发1.0才需要走到敌人面前两次。平方增长更好地反映了"高倍率的边际价值递增"。

**参数**：`k_damage = 5.0`

---

### 4.2 射程（range / bulletRange / targetRange）

射程采用**分段线性**，近战距离便宜，远程距离加速涨价。

```
P_range =
  r ≤ 1:  0           (贴身，无额外收益)
  r ≤ 3:  (r-1) × 1.2   (近战范围，便宜)
  r ≤ 6:  2.4 + (r-3) × 2.0  (中距离)
  r > 6:  8.4 + (r-6) × 3.5  (远程狙击)
```

射程取 `range`、`bulletRange` 中的较大值。`targetRange=99`（全图）统一视为 `r=15`（战场最长距离）。

| 射程      | P_range | 对应技能             |
| --------- | ------- | -------------------- |
| 1         | 0       | 匕首攻击             |
| 2         | 1.2     | 旋风斩、重击         |
| 3         | 2.4     | 突击盾               |
| 5         | 6.4     | 冰锥、连续射击、毒瓶 |
| 8         | 15.4    | 精准射击             |
| 15 (全图) | 39.9    | 箭雨、火球术         |

**为什么全图这么贵？**  
全图AOE意味着无论敌人怎么走位都能命中，这极大压缩了对手的对策空间。在16格战场上，"全图"就是"必中"。

---

### 4.3 多段攻击（multiShot）

多段攻击让一次技能发射 N 个弹幕，对弹幕碰撞系统有质变影响。采用**指数增长**。

```
P_multishot = (multiShot - 1) ^ 1.6 × 2.5
```

| 段数 | P_multishot |
| ---- | ----------- |
| 1    | 0           |
| 2    | 2.5         |
| 3    | 8.4         |
| 4    | 17.8        |
| 5    | 30.0        |

**为什么指数增长？**  
多段弹幕不仅增加了伤害（线性），还增加了：

- 弹幕碰撞中的拦截难度（对手需要更多弹幕来反制）
- 命中期望（多段更难被闪避完全规避）
- 弹幕等级叠加（多段高等级弹幕几乎无法被拦截）

---

### 4.4 AOE 范围（aoeRadius）

```
P_aoe = aoeRadius² × 3.5
```

| AOE半径 | P_aoe | 覆盖格数 | 对应技能 |
| ------- | ----- | -------- | -------- |
| 0       | 0     | 1        | -        |
| 1       | 3.5   | 3        | 火球术   |
| 2       | 14.0  | 5        | 箭雨     |

AOE范围的价值是面积级的，所以用平方定价。2格半径覆盖5格（超过战场1/3宽度），价值很高。

---

### 4.5 弹幕等级（bulletPriority）

弹幕等级决定了弹幕碰撞的胜负。更高等级 = 能穿透/截断低等级弹幕 = 更安全。

```
P_priority = (priority - 2) × 2.5  (priority > 2 时)
```

| 等级 | P_priority | 说明                             |
| ---- | ---------- | -------------------------------- |
| 1    | 0          | -                                |
| 2    | 0          | 基准等级（旋风斩、匕首、魔法盾） |
| 3    | 2.5        | 精准射击、突击盾                 |
| 4    | 5.0        | 连续射击、毒瓶、冰锥             |

等级 1-2 不收费（视为该类型的默认防御能力），等级 3+ 开始收费。

## 5. 特殊效果定价

### 5.1 控制效果

| 效果             | 公式              | 说明                                                   |
| ---------------- | ----------------- | ------------------------------------------------------ |
| 眩晕 (stun)      | `duration × 4.0`  | 使敌人跳过1个tick = 失去移动+行动，相当于直接赚取1tick |
| 冰冻 (freeze)    | `duration × 3.5`  | 同眩晕但附带额外视觉效果，比stun略便宜                 |
| 击退 (knockback) | `knockback × 2.5` | 改变敌人位置，配合地形/基地有额外价值                  |

1 tick 眩晕的价值：对手失去移动机会（可能被你追击或拉开距离）+ 失去攻击机会（你白赚一轮输出窗口）+ 失去弹幕拦截机会。大约相当于你多行动了1tick，所以定在4P是比较保守的。

### 5.2 DOT 效果

| 效果          | 公式                                    | 说明                       |
| ------------- | --------------------------------------- | -------------------------- |
| 燃烧 (burn)   | `burnRatio × burnTicks × ATK × 0.6`     | 延迟伤害，受ATK影响        |
| 中毒 (poison) | `poisonRatio × poisonTicks × ATK × 0.5` | 延迟伤害，通常持续时间更长 |

注意：DOT伤害不被防御减免（直接扣HP），所以价值系数比直伤略低（因为延迟）。

对于定价，用期望总DOT伤害折算：

```
P_dot = expected_dot_damage × 0.35
```

其中 `expected_dot_damage = ratio × ticks × ATK`。

以法师火球术为例：burnRatio=0.1, burnTicks=3, ATK=19 → 期望DOT=5.7 → P_dot=2.0

### 5.3 防御 Buff（defBuff）

```
P_defBuff = defBuff × 8.0
```

defBuff 是百分比形式的临时防御加成（如 0.5 = +50%防御）。其在当前 tick 有效，相当于减少即将受到的伤害。

| defBuff | P_defBuff | 说明       |
| ------- | --------- | ---------- |
| 0.3     | 2.4       | 轻防御     |
| 0.5     | 4.0       | 突击盾级别 |

### 5.4 真实伤害（true_damage）

真伤无视防御和防御Buff，完全穿透。对高防角色（战士 14DEF → 减伤 26%）价值更高。

```
P_true = damageRatio × 3.0  (额外费用，叠加在 P_damage 之上)
```

因为真伤同时绕过了防御和弹幕碰撞中的护盾类机制，比普通伤害有约30-50%的实际收益提升。

### 5.5 背刺机制（backstabRatio 独立于 damageRatio）

如果一个技能有独立的 `backstabRatio`，说明设计师期望玩家主动寻找背刺机会。背刺本身的1.3倍通用增伤不在此收费（那是游戏机制而非技能属性），但 `backstabRatio` 作为技能的额外倍率需要收费。

```
P_backstab = max(0, backstabRatio - damageRatio)² × 5.0
```

这确保"只能在背刺时触发的高额倍率"比"无条件高倍率"便宜一些（因为有条件限制）。

以刺客匕首为例：damageRatio=1.2, backstabRatio=2.4 → P_backstab = (2.4-1.2)²×5 = 7.2

## 6. 点数转消耗公式

### 6.1 资源分配总览

点数 P 决定了技能的"总资源成本"，然后分配到 SP、MP、CD 三个维度。

```
总资源成本 R = f(P)   (见 §6.2)
R = SP_weight × SP_cost_norm + MP_weight × MP_cost_norm + CD_weight × CD_cost_norm
```

### 6.2 P → R 映射曲线

```
R(P) = P^0.85 × 3.5
```

使用**次线性映射**（指数 0.85），意味着：

- 低点数技能的消耗相对更"贵"（防止无脑堆小技能）
- 高点数技能的消耗相对更"便宜"（鼓励使用高点数技能，但CD限制频率）

| P   | R(P) |
| --- | ---- |
| 5   | 13.8 |
| 10  | 24.8 |
| 15  | 34.8 |
| 20  | 44.2 |
| 25  | 53.2 |
| 30  | 61.9 |

### 6.3 资源维度划分

**默认分配比例**（可根据技能类型微调）：

| 资源 | 权重 | 换算                     |
| ---- | ---- | ------------------------ |
| SP   | 45%  | 1 SP = 1 资源单位        |
| MP   | 30%  | 1 MP = 1 资源单位        |
| CD   | 25%  | 1 CD tick = 4.5 资源单位 |

**为什么 CD 换算率是 4.5？**  
1 tick CD意味着技能至少间隔1tick才能再用。1tick内角色可以回约2SP+1MP=3资源，加上机会成本（不能使用该技能），估值4.5是合理的。

### 6.4 消耗生成算法

```
给定 P_total:

1. R = P_total^0.85 × 3.5

2. 分配：
   SP_raw = R × 0.45
   MP_raw = R × 0.30
   CD_raw = R × 0.25

3. CD = round(CD_raw / 4.5)
   最少 CD = 1（如果 P_total ≥ 4）

4. 剩余资源 = R - CD × 4.5
   按 SP:MP = 0.45:0.30 的比例重新分配剩余资源

5. SP_cost = round(SP_alloc)
   MP_cost = round(MP_alloc)

6. 硬限制：
   SP_cost ≥ 0, MP_cost ≥ 0
   CD ≥ 1 (P≥4时), CD ≤ 8 (硬上限)
   SP_cost ≤ 35, MP_cost ≤ 30 (单技能消耗上限)
```

### 6.5 技能类型微调

| 类型              | SP权重偏移 | MP权重偏移 | 理由                   |
| ----------------- | ---------- | ---------- | ---------------------- |
| melee             | +10% SP    | -10% MP    | 近战角色SP较高、MP较低 |
| projectile        | 默认       | 默认       | 均衡                   |
| dash              | +15% SP    | -15% MP    | 位移角色依赖SP         |
| targeted_aoe      | -10% SP    | +10% MP    | 施法者依赖MP           |
| teleport_backstab | +5% SP     | -5% MP     | 刺客SP池大             |

### 6.6 CD 点数置换（玩家自定义调参）

玩家在自定义技能时，可以手动调整 CD 来微调 SP/MP 消耗：

```
ΔCD = -1  →  ΔSP + ΔMP ≈ +4.5 资源单位（按比例分摊）
ΔCD = +1  →  ΔSP + ΔMP ≈ -4.5 资源单位（按比例分摊）
```

即：**多1 tick CD 可以抵扣约 4.5 点资源**，相当于少消耗约 2 SP + 1.5 MP（或其他组合）。

## 7. 完整示例

### 7.1 示例：解析"旋风斩" (warrior_whirlwind)

```
属性：
  type=melee         → P_template = 3.0
  damageRatio=1.0    → P_damage = 5.0 × 1.0² = 5.0
  range=2            → P_range = 1.2
  effect=normal      → 无额外
  bulletPriority=2   → P_priority = 0
  direction=forward_and_back → 无额外（模板内已隐含）
  multiShot=1        → P_multishot = 0

Σ P_attr = 5.0 + 1.2 = 6.2
高强度标签: 无
P_total = (3.0 + 6.2) × 1.00 = 9.2
R = 9.2^0.85 × 3.5 = 22.1

分配（melee: SP权重55%, MP权重20%, CD权重25%）:
  SP_raw = 22.1 × 0.55 = 12.2 → SP_cost = 12
  MP_raw = 22.1 × 0.20 = 4.4  → MP_cost = 4
  CD_raw = 22.1 × 0.25 = 5.5  → CD = round(5.5/4.5) = 1

实际值: SP=14, MP=0, CD=2
```

当前数值的 SP 略高、MP 为0、CD 多1tick。这个偏差在可接受范围内（实际游戏中的 SP=14 略高于公式的 12，但 CD=2 多出来抵扣了约4.5资源 → 剩余的SP应该更低才对 = 说明当前旋风斩可能略微偏贵）。

### 7.2 示例：解析"火球术" (mage_fireball)

```
属性：
  type=targeted_aoe  → P_template = 7.0
  damageRatio=0.9    → P_damage = 5.0 × 0.9² = 4.05
  targetRange=99→15  → P_range = 39.9
  aoeRadius=1        → P_aoe = 3.5
  effect=burn_debuff → P_burn = 0.1×3×19×0.35 = 2.0
  burnTicks=3        → 含在P_burn

Σ P_attr = 4.05 + 39.9 + 3.5 + 2.0 = 49.45
高强度标签: 远程(✓)、大范围(×, aoeRadius=1不够2)
P_total = (7.0 + 49.45) × 1.00 = 56.45
R = 56.45^0.85 × 3.5 = 102.0

分配（targeted_aoe: SP权重35%, MP权重40%, CD权重25%）:
  SP_raw = 102.0 × 0.35 = 35.7 → 硬上限35 → SP_cost = 35
  MP_raw = 102.0 × 0.40 = 40.8 → 硬上限30 → MP_cost = 30
  CD_raw = 102.0 × 0.25 = 25.5 → CD = min(8, round(25.5/4.5)) = min(8, 6) = 6

实际值: SP=10, MP=24, CD=5
```

可以看到，按照点数系统，火球术应该消耗 SP=35/MP=30/CD=6 → 但实际值远低于此。这说明**当前版本的火球术定价偏低**（或者说被刻意设计成法师的核心廉价技能）。这需要在调整时单独考虑角色定位。

### 7.3 示例：设计一个自定义技能

假设玩家想创建一个"雷电风暴"技能：

```
type=targeted_aoe     → 7.0
damageRatio=1.0       → 5.0
targetRange=99→15     → 39.9
aoeRadius=2           → 14.0
effect=stun_damage    → stunDuration=1 → 4.0
multiShot=2           → 2.5

Σ = 7.0 + 5.0 + 39.9 + 14.0 + 4.0 + 2.5 = 72.4
高强度标签: 远程(✓)、大范围(✓)、强控制(×,1tick)、多段(×) → 2个
synergy_tax = 0.12
P_total = 72.4 × 1.12 = 81.1

R = 81.1^0.85 × 3.5 = 139.4

分配(targeted_aoe: SP=35%, MP=40%, CD=25%):
  SP_raw = 139.4 × 0.35 = 48.8 → 硬上限35
  MP_raw = 139.4 × 0.40 = 55.8 → 硬上限30
  CD_raw = 139.4 × 0.25 = 34.9 → 硬上限8

结果: SP=35, MP=30, CD=8
```

这个技能非常强大（全图AOE 2格范围 + 1.0倍率 + 2段 + 眩晕），消耗也顶到了硬上限。CD=8意味着每8 tick只能用一次（一回合16tick最多用2次），符合预期。

## 8. 设计边界与硬限制

### 8.1 硬限制表

| 参数           | 上限 | 理由                                     |
| -------------- | ---- | ---------------------------------------- |
| damageRatio    | 3.0  | 超过3.0倍率配合高ATK可以一击秒杀任何角色 |
| multiShot      | 5    | 超过5段会让弹幕碰撞系统失效              |
| aoeRadius      | 3    | 超过3格覆盖过半战场，失去走位意义        |
| stunDuration   | 3    | 3tick眩晕 = 对手一回合中1/5时间无法行动  |
| freezeDuration | 3    | 同上                                     |
| CD             | 8    | 8tick CD意味着一回合最多2次              |
| SP_cost        | 35   | 超过角色最大SP池                         |
| MP_cost        | 30   | 超过除法师外所有角色的MP池               |
| range          | 15   | 战场只有16格                             |

### 8.2 P_total 上限

```
P_total_max = 100
```

超过 100P 的技能属于"理论上存在但实际无法使用"（消耗会顶满所有硬限制）。推荐自定义技能控制在 **8-40P** 之间。

### 8.3 防止极端情况的机制

1. **平方/指数增长**：高倍率和多段的价格非线性增长 → 堆单一属性到极端需要付出不成比例的代价
2. **协同惩罚**：多维度强力属性叠加额外惩罚 → 防止"全能技能"
3. **次线性映射 (P→R)**：高点数的边际消耗递减，但不能无限低 → CD 硬上限保证频率受限
4. **消耗硬上限**：无论点数多高，SP/MP/CD 都有天花板 → 点数超过一定值后"溢出"，防止天文数字消耗
5. **CD 硬上限 + SP/MP 硬上限**：即使 P=1000，也只能做到 SP=35, MP=30, CD=8 → 不会出现"永久CD但秒杀"

## 附录B：自定义技能设计建议

1. **先定模板，再加属性**：选择技能类型后，从底价开始逐步添加属性。
2. **控制在 10-30P**：这个区间的技能有明确的战术价值且消耗合理。
3. **30-50P**：强力技能，需要精心规划使用时机。
4. **50P+**：终极技能级别，消耗会顶满硬限制。
5. **避免同时堆高倍率+远程+多段+控制**：协同惩罚会让点数爆炸。
6. **CD比SP/MP更"贵"**：能用SP/MP解决的问题不要堆CD（CD直接限制使用频率）。
