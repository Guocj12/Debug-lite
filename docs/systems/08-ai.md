# AI 系统 详细设计

> 所属：Debug-Lite v3　本文档精确到代码逻辑（自然语言，不写代码）。与 `../v3-design.md` 冲突时以本文档为准。

## 1. 职责

- AI 程序 AST 定义与静态校验。
- 续执行解释器（每个 tick 跑出一个行动后挂起）。
- 合法性检测（防死循环、防选不出行动）。
- Blockly 编辑器对接（积木 ↔ AST，段位门控）。

## 2. 依赖

- `rng.js`（随机）、`unlock.js`（段位门控）。
- `ast.js`（结构定义与校验）、`runtime.js`（解释器）。

## 3. 数据结构

- 程序：`{type:"program", version, body}`。
- 节点类型：`literal`、`get`、`bullets`、`var`、`set`、`getVar`、`arith`、`cmp`、`logic`、`random`、`if`、`loop`、`break`、`function`、`call`、`action`、`seq`。
- 执行上下文 `AiContext`：`pc`（指令指针/调用栈）、`vars`（变量作用域，跨 tick）、`halted`（是否挂起）、`stepCount`（步数计数）。
- 执行轨迹 `trace`：本 tick 每求值一个节点追加一条记录（节点 id、类型、求值结果，如条件真假、分支走向、循环次数、最终行动）。

## 4. 核心流程（代码逻辑）

### 4.1 静态校验 `validate(program, tier)`

1. 结构校验：只允许白名单节点；字段类型/嵌套深度合法。
2. 合法性检测：
   - 程序整体必须存在至少一个可达 `action` 节点。
   - 每个 `loop` 的 `body` 内必须存在至少一个 `action` 节点（含嵌套函数内的循环）。
3. 段位门控：程序用到的语法节点必须都在 `tier` 已解锁集合内（`random`/`loop`/`function` 等），否则拒绝。
4. 返回通过或带原因的失败。

### 4.2 创建上下文 `createContext(program)`

1. `pc` 指向顶层 `seq` 第一条语句。
2. `vars` 为空作用域；`halted = false`；`stepCount = 0`。

### 4.3 续执行 `resume(ctx, state, rng)`

1. 从 `ctx.pc` 继续逐节点求值。
2. 各节点语义：
   - `seq`：依次求值子语句。
   - `if`：求值条件，进入 then 或 else。
   - `loop`：次数循环按次数迭代；条件循环每次先求值条件。
   - `break`：跳出当前循环。
   - `var`/`set`/`getVar`：读写 `ctx.vars`。
   - `function`：注册命名函数；`call`：进入函数体（维护调用栈）。
   - `random`：用 `rng` 判定概率分支。
   - `action`：记录「下一条语句」为断点，`halted = true`，返回该行动。
3. 每求值一个节点 `stepCount += 1`；超过上限（如 10,000）→ 返回保底行动 `defend` 并重置 `pc` 到入口，记录诊断。
4. 每求值一个节点，向 `ctx.trace` 追加一条轨迹（节点 id、类型、求值结果），供前端实时展示。
5. 读战场状态为只读快照；仅 `vars` 可写。
6. 战斗结束时销毁上下文。

### 4.4 段位门控（编辑器）

1. `availableNodes(tier)` 返回该段位可用的积木集合。
2. 未解锁积木在 Blockly 工具盒中隐藏或置灰。
3. 编辑器生成 AST 时实时调用 `validate` 的合法性规则，提示「循环缺少行动」等错误。

### 4.5 执行轨迹输出

1. `resume` 每次调用返回：本 tick 行动 + 本次执行产生的 `trace`。
2. 引擎把 `trace` 放进本 tick 状态差异，前端据此高亮积木、展示「某条件是否判断成功、运行到哪一步」。

## 5. 边界与异常

- 无 `action` 的程序 → 校验拒绝。
- 循环体无 `action` → 校验拒绝（防死循环）；运行时步数上限兜底。
- 变量未声明 → 按 0/false。
- 函数递归 → 限制调用深度，超限返回保底行动。

## 6. 对外接口

- `validate` / `createContext` / `resume` / `availableNodes`。
- 引擎每 tick 对双方各调用一次 `resume`，并取回 `ctx.trace` 放入本 tick 状态差异。

## 7. 测试要点

- 合法性检测：缺 action、循环缺 action、未解锁语法被拒绝。
- 续执行：两个 tick 依次产出不同行动，断点正确。
- 变量跨 tick 持久。
- 步数上限兜底。
- 函数调用与调用栈、递归深度限制。
- 执行轨迹：条件真假、分支走向、最终行动被正确记录。
