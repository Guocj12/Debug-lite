# AI 系统 详细设计

> 所属：Debug-Lite v3　本文档精确到代码逻辑（自然语言，不写代码）。与 `../v3-design.md` 冲突时以本文档为准。

## 1. 职责

- AI 程序 AST 定义与静态校验（结构 + 合法性 + 段位门控）。
- 续执行解释器（每 tick 跑出一个行动后挂起）。
- 执行轨迹 `trace`（供前端高亮与排查）。
- 程序规范化与 `programHash`。

## 2. 依赖

- `rng.js`（每 tick 每用途派生流）、`unlock.js`（段位门控）。
- `ast.js`（结构定义与校验）、`runtime.js`（解释器）。

## 3. 数据结构

- 程序：`{ type:"program", version:1, body:{ type:"seq", statements:[...] } }`。
- 节点：`literal` `get` `var` `set` `getVar` `arith` `cmp` `logic` `random` `if` `loop` `break` `function` `call` `action` `seq`（**共 16 类**，与 `ai/ast.js` 的 `NODE_TYPES` 逐值一致）。
- **已移除节点：`bullets`（2026-09-17，用户决策）**：AI **无法观测弹幕**——弹幕在**生成当 tick 就全量解算完毕**（D-20），下一 tick 战场上必然为空，因此"读弹幕"在语言里没有任何可用语义。移除后 `{ "type":"bullets" }` 走白名单 → 校验期 `unknown_node` 拒绝。**这是设计，不是缺陷**：需要"反应式"策略时，AI 只能依据**可观测量**（`self`/`enemy` 的 `hp/x/facing`、`field` 等）做判断，例如"敌方逼近 → 后撤/格挡"而不是"躲某枚弹幕"。
- **节点字段与取值（以 `ai/ast.js` + `ai/runtime.js` 实现为准）**：
  - `get`：单个 `path` 字符串（白名单路径，如 `self.hp` / `enemy.x` / `field.cellPx`）——**不是** `target`+`field` 两字段。
  - `logic`：`op` / `left` / `right`，`op ∈ {and, or}`（**仅此两值**；`not` 未实现，其它取值一律求值为 `false`，见 §4.3）。
  - `random`：`prob` / `then` / `else`——**同一个节点按所在位置有两种用法**：**语句位 = 概率分支**、**表达式位 = 布尔**（返回值为 `true`/`false`，不再返回 `then`/`else` 子树）；两种用法都在实际求值时消耗一次 `ai` 流，详见 §4.3 第 2 条与 §4.4。
  - `arith`：`op ∈ {+ - * /}`（**无 `%`**；`/` 为 `Math.floor` 整除）。
  - `cmp`：`op ∈ {< > <= >= == !=}`。
  - `loop`：`kind ∈ {count, while}`（**仅此两值**；`ast.js` 目前只做"字符串"类型校验，未做枚举校验，`runtime.js` 仅把 `count` 当计数、其它值一律按 `while` 处理）。
  - ⏳ **计划（未实现）**：`logic.op` / `loop.kind` / `arith.op` 的**枚举校验**已登记为待补（现状是"非枚举值静默退化"，不是错误）。
- **执行上下文 `AiContext`**（**必须可序列化**；字段以 `runtime.serializeContext` 实际产出为准）：
  ```jsonc
  { "programHash":"…", "entry":"body",
    "frames":[ { "kind":"seq", "path":"body.s[0]", "childIndex":0,
                 "remaining":null, "condValue":null, "fnScope":null } ],
    "vars":{ "cd1":0 }, "halted":false, "stepCount":0, "trace":[],
    "stepLimit":10000, "traceLimit":2000, "recursionLimit":64, "traceTruncated":false }
  ```
  - 与旧描述的差异（**以实现为准**）：帧内是 **`path`**（不是 `nodeId`），**无 `phase`**、**无 `scopeDepth`**；多出 `stepLimit` / `traceLimit` / `recursionLimit` / `traceTruncated` 四个顶层字段；变量作用域挂在内存的帧上，序列化时只输出 `fnScope` 的浅拷贝。
- **执行轨迹条目**：`{ seq, path, nodeType, phase, result?, depth }`——**`result` 仅 `action` 节点才有**（值为该 action 名，供 T-AF-6 核对"末条 action 与返回值一致"），其余节点的条目不带 `result`。

## 4. 核心流程（代码逻辑）

### 4.1 隐式主循环（D-100，**重要**）

- ⚠️ **AI 的最外层是一个无法跳出的 `while(true)`**：程序执行到最后一条语句后**自动回到第一行**继续执行。
- 该结构由**引擎隐式提供**，不需要（也不允许）玩家自己写外层循环；在编辑器中它**显式可见且无法删除**（P6）。~~Blockly~~ **已废弃**：现行前端为表单式 AST 编辑器（`docs/frontend-spec.md` v3 §12），该行根节点由界面固定渲染、不可删除。
- 因此"程序跑完"不代表结束，只代表回到开头；AI 是**永久循环的有状态脚本**。

### 4.2 静态校验 `validate(program, tier)`

1. **结构校验**：白名单节点、字段类型、深度 `≤32`、节点数 `≤2000`、字节 `≤256KB`、拒绝危险键（`__proto__`/`constructor`/`prototype`）。
2. **合法性检测（D-101）**：
   - `loop` 体内**所有分支都必须至少包含一个 `action`**（比"循环体含 action"更严格）——包括 `if/else` 的**每个分支**、嵌套循环、函数体内的循环；
   - **允许 `while(true)`**；但若某分支不含 `action`，该分支一旦进入就永远产不出行动 → **拒绝**；
   - 循环外 `break`、未知函数调用等结构错误 → 拒绝。
3. **段位门控**：程序用到的节点类型必须都在 `tier` 已解锁集合内（紫段位解锁 `random` + 扩展运算符）。
4. 返回 `{ok, errors:[{path, code, message}]}`——**错误必须带 `path`**，供编辑器定位/高亮节点（P6 表单式编辑器按 `path` 定位，见 `docs/frontend-spec.md` v3 §12）。

### 4.3 续执行 `resume(ctx, snapshot, rng)`

1. 从 `ctx` 的 `frames` 栈顶继续，按**微步骤**（`stepOnce`）推进：进入节点 / 求值第 i 个子节点 / 退出节点。
2. 各节点语义：
   - `seq`：依次求值子语句；**顶层 `seq` 结束时回到入口**（隐式主循环）。
   - `if`：求值条件 → 进入 then 或 else。
   - `loop`：`count` 用帧内 `remaining` 迭代；`while` 每次迭代**先求值条件**。
   - `break`：以**信号对象**向上找最近的 `loop` 帧并退出（不用异常穿透用户逻辑）。
   - `var/set/getVar`：读写当前作用域；未声明读取返回安全默认值 `0`/`false`。
   - `function`：进入顶层 `seq` 时**先注册全部函数（hoisting）**，故"先调用后定义"合法。
   - `call`：**压入新帧 + 新作用域**（独立作用域，D-103）；可读取外层变量，内部 `var` 不泄漏；**无参数、无返回值**（D-102）；递归深度上限 64。
   - `random`（**一个节点、两种用法，按出现位置分派**；2026-09-17 用户决策 A 修正语义）：
     - **语句位**（作为某条 `seq.statements` 的一项）= **概率分支**：求值 `prob` 并消耗一次 `ai` 流后，**真的进入 `then` 或 `else` 分支执行**
       （分支为 `seq` 时取 `statements`，单节点按一个语句处理；分支内的 `action`/`set` 等照常推进，且**跨 tick 可恢复**）；
       `else` 缺省时视为空分支直接跳过，**与 `if` 缺 `else` 的行为一致**。
     - **表达式位**（`set`/`var` 的值、`if.cond`、`loop.cond` 及运算子节点等）= **布尔**：求值为 `rng.chance(prob,'ai')` 的 `true`/`false`
       （`true` 的概率为 `prob`，`prob=1` 恒 `true`、`prob=0` 恒 `false`）；此时 `then`/`else` 字段**不参与求值**，求值结果也**不是 AST 子树对象**。
     - 两种用法都**只在真正求值该节点时消耗一次 `ai` 流**（`purpose='ai'`；D-91「每 tick 每用途派生流」）；挂起中或未走到的分支不消耗。
   - `action`：把该 action 作为返回值，`halted = true`，**把断点记在 action 的下一条语句**。
3. 每推进一个微步骤 `stepCount += 1`；超过 `STEP_LIMIT`（10000）/tick → 返回 **`wait`**、**重置到入口**、记录 `ai.step.limit`(**warn**) 诊断（D-81）。
4. 每推进一个微步骤追加一条 `trace`；**累计上限 2000 条（A-9e 总量冻结：超过后不再记录，B16 定稿）**，截断时记 `trace.truncated`(warn) 一次。
5. 读战场状态为**只读快照**（D-107 白名单投影 + 深冻结）；仅 `vars` 可写。
6. 内部异常（非用户可控）→ 返回 `wait` + `ai.error`(err) 日志 + trace，**绝不抛穿引擎**。

### 4.4 随机语义（D-90/D-91）

- **每局一个全局种子**；**每 tick 每用途各派生一条流**：`hash(seed, tick, purpose)`，`purpose ∈ { ai, crit, dodge }`。
- 各用途互不干扰：AI 多消耗随机**不会**平移暴击/闪避的随机序列（回放最稳）。
- 挂起/未走到的分支**不消耗**随机。
- `random` 节点的一次**实际求值**从 `ai` 流取一个数：结果 = `chance(prob)`，即 **`true` 的概率为 `prob`**（语句位用它选分支，表达式位直接作为布尔值，§4.3）。

### 4.5 只读快照与安全默认值

- 白名单投影：`self{hp,atk,def,sp,mp,x,baseHp,facing}` / `enemy{同}` / `field{fieldPx,cellPx}`。
  - ⚠️ **不含 `bullets`**：AI 无法观测弹幕（弹幕当 tick 全解算，D-20，见 §3 的移除说明）；`bullets` 节点已从语言白名单删除。
    （实现备注：`server/runner.js` 的快照目前仍保留 `bullets` 字段以维持契约形状，而 `runtime.getPath` 为通用点分路径解析——若 `get.path` 白名单校验补齐，`bullets[*]` 应一并从可读路径中剔除。）
- 深冻结后注入；`x` 为 **px**（与战斗一致）。
- 越界/非法读取 → 安全默认值（数值 `0`、布尔 `false`）并记 trace，不抛错。

### 4.6 程序规范化与版本

- `canonicalize(program)`：节点字段按白名单顺序输出、对象键排序、去空白 → `sha256` → **`programHash`**。
- 用途：缓存键、快照去重、回放校验（帧内记录 hash 可检测篡改）、诊断"这场用的是哪个版本 AI"。
- `version` + `migrations[n→n+1]`；高于当前支持版本 → 拒绝 `ai_version_unsupported`。

### 4.7 与引擎 / API 的接口

- 引擎步骤 3 调用：`resume(ctx, snapshot, rng)` → `{ action, trace }`。
- `POST /api/v1/ai/validate` → 失败时 `{code:'ai_invalid', details:[{path, code, message}]}`。
- `POST /api/v1/ai/compile` → `{programHash, stats:{nodes, depth, usedNodeTypes}}`。
- `POST /api/v1/ai/battle` → 服务端**重新执行**，不信任客户端结果。

### 4.8 段位门控（编辑器）

- `availableNodes(tier)` 返回该段位可用节点集合；未解锁节点不可添加/置灰（P6）。⏳ **计划（未实现）**：P6 编辑器仍未落地，且现行前端设计（`docs/frontend-spec.md` v3 §12）为**纯 DOM 表单式 AST 编辑器**——原文的「Blockly 工具盒/积木」写法已废弃。
- **段位累计可用节点数（实算；2026-09-17 删除 `bullets` 节点后重算）**：基础节点 9（`ai-nodes.json` 的 `base`，原 10 含 `bullets`）＋各段位增量权限展开：

  | 段位 | 该段位新增权限（`unlock.json`） | 展开新增节点 | **累计可用节点数** |
  |---|---|---|---|
  | `common` | `if` | `if` | **10** |
  | `rare` | `loop`、`while`、`break` | `loop`、`break`（`while` 折叠为 `loop`，不新增） | **12** |
  | `epic` | `random`、`logic`、`arith_ext` | `random`、`logic`（`arith_ext` 未实现 → 不授予） | **14** |
  | `legendary` | —（无 `aiNodes`） | — | **14** |
  | `mythic` | `function`、`call` | `function`、`call` | **16** |

  复算命令：`node -e "const u=require('./server/core/unlock.js');for(const t of ['common','rare','epic','legendary','mythic'])console.log(t,u.availableNodes(t).length)"`
- 编辑器实时调用 `validate` 的合法性规则（含**分支 action** 规则），给出带 `path` 的提示。

## 5. 边界与异常

| 情形 | 行为 |
|---|---|
| 无 `action` 的程序 / 某分支无 `action` | **校验期拒绝** |
| 步数超限 | 返回 `wait` + 重置入口 + `ai.step.limit`(warn) |
| 递归超深 | 返回 `wait` + `ai.depth.limit`(warn) |
| 变量未声明 | 安全默认值 `0`/`false` |
| 非法 action 名 | 归一化为 `wait` + `action.invalid`(warn) |
| 内部异常 | 返回 `wait` + `ai.error`(err) 日志，不中断战斗 |
