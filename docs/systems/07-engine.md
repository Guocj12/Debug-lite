# 战斗引擎 详细设计

> 所属：Debug-Lite v3　本文档精确到代码逻辑（自然语言，不写代码）。与 `../v3-design.md` 冲突时以本文档为准。

## 1. 职责

- 编排 tick 循环，调用各系统。
- 维护战场状态（双方角色、基地、弹幕、效果、事件）。
- 结束判定与确定性保证。

## 2. 依赖

- `rng.js`、`field.js`、`roles.js`、`skills.js`、`bullets.js`、`effects.js`。
- `ai/runtime.js`（AI 续执行）。

## 3. 数据结构

- 战场状态：`tick`、`seed`、`field`、`players{p1,p2}`、`bases`、`bullets[]`、`events[]`、`rngState`。
- 玩家运行时：`x`、`facing`、`hp/mp/sp`（当前）、`maxHp/maxMp/maxSp`、`atk/def`（最终）、`cooldowns{}`、`effects[]`、`aiContext`（AI 断点）。

## 4. 核心流程（代码逻辑）

### 4.1 创建战斗 `createBattle(config, seed)`

1. 用种子初始化 RNG。
2. 实例化双方角色（模板 + 品质 + 插件）、技能。
3. 初始化 AI 上下文（双方各一个，指向各自程序入口）。
4. 设置初始位置（x=3 / x=12）、基地血量、朝向。

### 4.2 单 tick `step()`

依次执行：

1. `tick += 1`，派生本 tick 子种子（`hash(seed, tick)`）。
2. 结算持续效果（增减属性）。
3. 双方 AI 续执行，各产出本 tick 行动；同时输出 AI 执行轨迹。
4. 结算控制效果：把 AI 返回的行动复写为该效果（位移/眩晕）。
5. 双方同时行动：
   - 转向：翻转朝向。
   - 防御：本 tick 减伤标记。
   - 位移/技能：生成弹幕、更新位置（先计算，再统一落位）。
   - 背击判定所需的「释放前位置与朝向」在本步开始前做快照。
6. 角色移动与角色碰撞（双方相向或同格 → 阻挡/碰撞处理）。
7. 弹幕推进与碰撞（调用 `bullets.resolveTick`），命中结算（伤害管线 + 新效果）。
8. 资源恢复：`mp += regen`、`sp += regen`，上限封顶。
9. 结束判定 `judge`。
10. 产出本 tick 状态差异与事件（行动、移动、弹幕、命中、效果、资源变化、AI 轨迹）。

### 4.3 伤害管线 `dealDamage(attacker, defender, params)`

1. 闪避判定：defender 有 `dodgeChance` 且非必然命中 → 判定成功则无伤、生成闪避事件、结束。
2. 计算基础伤害：普通 `max(1, floor(atk × multiplier × (1 - def/(def+40))))`；真实伤害 `max(1, floor(atk × multiplier))`。
3. 背击判定：见下表，命中为背击 → 伤害 × 1.5。
4. 暴击判定：`critChance` 命中 → 伤害 × 1.5（默认）；与背击可叠加。
5. 吸血：attacker.hp += 伤害 × `lifesteal`，上限封顶。
6. 应用伤害到 defender，生成命中事件。
7. 触发词条附加效果（眩晕/击退/拉近/持续伤害等）。

**背击判定依据**（`params.attackType` 决定）：

| 攻击类型 | 判定 |
|---|---|
| 近战 / 位移 | 用**释放技能前**两个角色的相对位置与朝向（本 tick 行动前快照）：攻击方位于受击方朝向的反方向（身后）→ 背击 |
| 平射弹幕 | 弹幕飞来的方向与受击方朝向：来自身后 → 背击 |
| 垂直弹幕 | 永不触发背击 |

### 4.4 结束判定 `judge(state)`

按优先级：

1. 一方基地血量 ≤ 0 → 另一方胜；双方同时 → 平局。
2. 一方角色血量 ≤ 0 → 另一方胜；双方同时 → 平局。
3. `tick >= 48` 之后：每 tick 双方基地与角色**同时**扣除各自血量上限的 6.25%（向上取整），直到触发 1 或 2。

- 6.25% × 16（48→64）= 100%，向上取整保证即便角色回血，基地血量也必然在 64 tick 前归零，战斗一定结束。
- 同时发生按「基地优先于角色」的优先级；同级同时发生 → 平局。

### 4.5 快进 `runFull()`

1. 循环调用 `step()` 直到 `judge` 返回非空。
2. 返回完整 tick 序列与最终结果，结果必须与逐 tick 回放一致。

### 4.6 状态差异输出（供前端绘制）

1. 每个 `step()` 结束后生成「两 tick 间全局状态差异」：
   - 角色：位移起止、朝向变化、血量/资源增减、新增/移除的 buff 粒子。
   - 弹幕：飞行路径、命中格、**两弹幕在哪一格碰撞**（碰撞格坐标与胜者）。
   - 基地：血量增减。
   - 事件：有序事件列表。
   - AI 轨迹：双方 AI 本 tick 的执行轨迹。
2. 前端依据差异插值绘制运动与粒子，不自行重新模拟。

## 5. 边界与异常

- 无效技能行动（资源不足/冷却中）：不扣资源、不产生效果，视为空行动；移动类行动仍照常。
- 确定性：所有随机走 RNG；遍历顺序固定（先 p1 后 p2、先近后远、先早后晚）；事件顺序固定。
- 同一 tick 双方同时行动：先各自计算意图，再统一落位，避免先后影响结果。

## 6. 对外接口

- `createBattle`、`step`（含每 tick 状态差异 + AI 轨迹）、`runFull`、`judge`：供战斗 API、排位离线结算、AI 测试使用。

## 7. 测试要点

- 同种子两场战斗 tick 轨迹完全一致。
- `runFull` 与逐 tick `step` 结果一致。
- 结束三路径（基地/角色/超时扣血）+ 平局。
- 无效行动、资源恢复、防御减伤。
- 状态差异：位移、弹幕路径与碰撞格、buff 粒子、基地扣血正确输出。
- 背击/暴击：各 1.5 倍且可叠加；近战/平射/垂直判定正确。
