### 8.2 处置（一个提交，`D-163`）

1. **权威解析**（H-1）：`loadout.resolveItems(loadout, warehouse)` 按 uid 从**服务端仓库**取回物品（客户端 `stats/templateId/quality/params/slots` 丢弃；未知 uid / 类别不符 → 错误）。`account.js` 的 `createSlot`/`saveConfig`/`activateConfig` 全走它，且**落盘的永远是解析后的正文**；`loadout.buildPanel` 在有仓库时同样先解析（纵深防御：历史遗留的被篡改快照也失效）；HTTP 配置路由**不再把 `body.warehouse` 传下去**（客户端镜像只在服务端存储不可用时降级并记 warn）。另加审计：客户端正文与仓库副本指纹不一致时记 `api.reject`（`client_item_body_ignored`）。
2. **同配置内唯一 + 不完整配置也要查引用**（H-2）：`resolveItems` 对 角色 + 3 技能 + 全部插件引用做**全 uid 去重**（`同一物品被多处引用` / 既有 `同一插件被双处引用`）；`skills.length > 3` 直接 409（不再静默截断）；`validateLoadout` 的引用校验**去掉 `errors.length === 0` 前置**，且 L6 对非出战槽的不完整配置改为"只容忍缺失类错误"（`hardErrorsOf` 用 `loadoutMissingDetails` 的 `{path,message}` 精确抵消，不写死文案）。
3. **跨配置独占**（用户裁定）：`exclusivityDetails(archive, slotId, loadout)` 以 `archive.warehouseUsage`（单一真源）判定，save/create/activate 三处生效 → 409 **`item_in_use`**（`details` 逐 uid + 占用它的 slotId）。`usage[uid].slotIds` 从此至多一项（**推翻 D-159②**）。
4. **发放 uid 与丢失可审计**（H-3）：`archive.allocateGrantUids(warehouse, items)` 在**写 journal 前**把撞车 uid 重映射为仓库内空闲 uid；`grantBox` 把重映射后的 `items` 回给路由 → **响应 = journal = 档案**；`box.opened` apply 的撞车分支由静默 `continue` 改为 `error` 日志（`store.warehouse.uid_collision`）+ `dropped`/`droppedUids` 入 `grantIds`。
5. **前端配套**：`slot-pick`/`plugin-pick` 把"点了必然 409"的候选**预先标灰 + 行内写原因**（`已被配置N使用（一件物品同时只能装配到一份配置）` / `本配置已在其它位置使用（一件物品只能占一个位置）` / `已被装配（请先拆卸）` / 既有 `此槽只能装 <type>`）；"已装配"由已登记的 `slots[].pluginUid` 推导（不为 UI 扩字段契约）。
6. **连带修正**：`scripts/play.js` 改为**逐侧仓库**（`npm run play` 曾被解析规则打坏——`battle.runBattle` 原来把同一份 `wh2` 给双方，而 p2 是内置 bot，其 `bot_role`/`bot_skill1..` 不在玩家仓库里）；`ranked.syntheticVerifiedWarehouse` 补上"角色与技能也在其中"（修前只有插件项，退化路径会报 `物品不在仓库`）。
