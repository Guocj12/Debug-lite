## 发现的问题

### P0-1（阻塞）函数作用域链跨 resume 不重建 → D-103 泄漏 + A-9d 抛穿引擎

**位置**：`server/ai/runtime.js:137,157,75`（配合 200-202）。

**问题**：`resume()` 每次调用以 `scopes = [ctx.vars]` 重建作用域链，**没有从 frames 恢复已挂起函数帧的 fnScope**。fnScope 仅在 `call` 语句处理时压栈（F-200），只对"当次 resume 内"的函数体生效。于是：
1. **函数体在 action 处挂起、下一 tick 继续执行**（A-5 明确要求"断点位于函数内部；下一 tick 从函数内继续"）时，后续 `var/set/getVar` 落到根作用域——`var local` 泄漏到根（D-103"内部 var 不泄漏"违背）。
2. **fn 帧跨 resume 完成时**，F-157 `scopes.pop()` 弹出的是 `ctx.vars`（fnScope 本就不在链上）→ scopes 变空数组。
3. 之后同一 tick 内任何 `writeVar`（F-75 `scopes[0][name] = value`）对 undefined 赋值 → **TypeError 直接抛出**，违背 A-9d"内部异常绝不抛穿引擎"。

**复现**（合法程序，ast.js B13 校验全过：无循环、call 已定义、函数体语句合法）：

场景 A（函数体 action 后有语句）：
```
var g = 1
function f { var local = 99; action skill1; set local = getVar local }
call f
set g = g + 10
```
- tick1 → skill1（正常）；tick2 → **TypeError: Cannot set properties of undefined (setting 'g')**，resume 抛异常。

场景 B（函数返回后同 tick 有 set，最常见形态）：
```
var g = 1
function f { action skill1 }
call f
set g = 2
```
- tick1 → skill1；tick2 → **同样 TypeError**。

即任何"函数调用 + 函数体/后续含变量写"的程序在 B14 运行时必然崩溃；B16 接入战斗引擎后即打穿 A-9d。

**修复方向（已在临时副本实证有效）**：resume 入口（F-137 后）从 frames 重建链：
```js
const scopes = [ctx.vars];
for (const f of ctx.frames) if (f.fnScope) scopes.push(f.fnScope);
```
（F-157 弹栈配对在重建后自动成立——scopes 栈顶即完成帧的 fnScope；可再加身份校验 `scopes[scopes.length-1] === top.fnScope` 防御。）复现两个场景改为：A 场景 tick2 后 g=11、local 不泄漏、不抛；B 场景 g=2、不抛。

**必须配套回归测试**（补齐第 10 项"断言过弱"缺口，断言"不抛 + 值正确 + 不泄漏"）：
1. 函数体 action 后仍有 var/set（跨 resume 续执行）；
2. call 后同一 tick 顶层 set（scopes 不误弹）；
3. 递归跨 resume 作用域链正确（可选）。
