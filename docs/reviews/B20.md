### P1（必须当批修复）

**P1-1（B20 聚合路径崩溃；B19 P1-1 防御姿态同族复现）`buildPanel` 技能聚合对未知 `templateId` → TypeError 500 / 未知 `quality` → RangeError 500；且 `validateLoadout` 对这两种注入态全部放行（/loadout 200）**

位置：`server/loadout.js:120`（`skills.instantiateSkill(sk.templateId, sk.quality || 'common', STUB_RNG)`）。链路：`instantiateSkill` → `items.generateSkillItem`（skills.js:28），`skillMap['nope']` 为 undefined → `t.baseMultiplier` 抛 `TypeError: Cannot read properties of undefined (reading 'baseMultiplier')`；`sk.quality='platinum'` → `getQuality` 抛 `RangeError: 未知品质`。buildPanel 无 try/catch → POST /panel **500 internal_error**。前置校验失效：validateLoadout 只查结构（kind 等）/引用/门控，**不查 templateId ∈ skillMap、quality ∈ TIERS**——实证 `/loadout` 对 `templateId='nope_not_a_template'` 的 loadout 返回 **200 ok:true**（校验服务接受非法配置），`/panel` 同输入 → **500**（真实 socket 双证）。触发构造成本极低：合法 loadout 改一个技能 templateId 为垃圾值（保留插件引用即触发聚合路径；无插件时直透不触发——但装配引用是常态）。CLI panel 同路径（服务端 500 → CLI 优雅 exit 1，不崩溃）。这是 B19 P1-1（skills 畸形 → 500）修复后同族输入防御的第二次漏网，且洞在 **B20 新增代码路径**。

修复（推荐校验层语义化，与 I-12a 结构校验同层）：validateLoadout 结构段补——
① 角色/技能 `templateId` 存在性（roleMap/skillMap 数据表命中，缺失/未知 → `loadout_invalid`「未知模板」）；
② 技能 `quality ∈ TIERS`（五项品质表，未知 → `loadout_invalid`）。
必配回归：core ×2（未知 templateId + 插件引用 → `{ok:false}` 不抛；未知 quality 同理）+ HTTP ×2（/loadout 与 /panel 双端点 409 而非 500）。另可将 buildPanel 聚合包 try 兜底或 `skillMap.has` 防御（次选，兜底不改变校验放行的语义缺口）。
