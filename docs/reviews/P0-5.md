## 过程发现（全部实测、已写入 scripts/README.md）

1. `checkStaticRandEval` 正则缺 `g` 标志 → `exec()` 死循环（本批最大调试坑）。
2. `--test-coverage-*` CLI 阈值是**聚合**语义（早前"每文件"表述修正）；gate 项 7 为更严的每文件语义。
3. **V8 precise coverage 只统计会话开始之后加载的脚本** → 门禁进程预加载 `shared/log.js` 会使其覆盖率永久残缺（实测 47.8~77.6%）→ 懒加载 + 项 7 最先执行。
4. 同进程第二次嵌套 `run()` 流永不结束（与 coverage 无关）；覆盖率会话中嵌套 run() 破坏外层数据 → 套件内禁嵌套 run()，`runSuite` 真实路径由 `npm run gate` 本体自验证。
5. 门禁进程形态下 `main()` 用 `process.exitCode`（可测试），CLI 退出码语义不变（cmd `if errorlevel` 复测 exit 0/1 均正确）。
