## 2.5 现场故障与修复（2026-09-22，用户报告）

**现象**：用户在浏览器用 `test01` / `12345678` 登录，页面显示 `用户名或密码错误`。

**证据链（先查证，不猜）**

1. 服务端日志：`POST /api/v1/auth/login -> 401` 确实落在本机在跑的实例（pid 26048，`npm start`，数据根 `runtime/`）—— 说明请求到达正确服务。
2. 存储层：`runtime/index.json` 含且仅含一个玩家 `pl_f3595c4d80ca0e00` / `u_20996175`（= test01）；`runtime/journal/2026-09.jsonl` 仅 1 条 `account.created`（seq=1）—— 说明建号记录就是本批演示那一次，密码即 `12345678`。
3. **对照实验**（同一账号、四种输入直打真实服务）：

| 提交的密码 | 结果 |
|---|---|
| `12345678`（半角 8 位） | **HTTP 200 登录成功**（连测两次均 200） |
| `1234568`（半角 7 位，用户最初给的） | 401 `invalid_credentials` |
| `１２３４５６７８`（**全角** 8 位，中文输入法） | 401 `invalid_credentials` |
| `12345678 `（末尾多一个空格） | 401 `invalid_credentials` |

**结论**：服务端账号与密码无误（200 可复现）；浏览器那次提交上去的字符串与 `12345678` 不同。由于服务端文案有意不区分「用户不存在 / 密码错」（反枚举），单看文案无法定位，因此下面顺手补掉两处**会放大该问题**的实现缺陷。

**本次修复（仅前端 + 文档；未动 `/api/v1` 契约）**

| # | 修复 | 依据 |
|---|---|---|
| 1 | **业务失败即清空当前屏的密码类输入框**（保留用户名/昵称）；传输失败仍保留全部输入 | 新增分册 §8 B-14。修前密码框残留旧值 → 用户再次输入变成"追加"（例：残留 `1234568`，补打 `8` 得到 `12345688`），表现为反复 `invalid_credentials` 且毫无线索 |
| 2 | **用户名校验与提交一律 `trim()`**；纯空白视为空输入 | 新增分册 §8 B-15（复制粘贴常带空格；密码不 trim，仅提示排查） |
| 3 | `invalid_credentials` 增加可排查指引：`注意：密码区分大小写，且不要有多余空格或全角字符` | 分册 §6 该行（实测三种输入都落到本码，原文案不足以排查） |
| 4 | 新增回归用例 **FL-12**（失败清密码框、保留用户名）/ **FL-13**（7 位 / 全角 / 末尾空格三种形态都落 `invalid_credentials` + 指引文案）/ **FL-14**（用户名 trim、纯空白不发请求） | 分册 §10.3；前端用例 35 → **38** |

**复现验证（对用户正在使用的 3000 端口实例，DOM 级走真实页面代码）**

```
[1] test01 + 1234568       → 登录页 注意：密码区分大小写…：用户名或密码错误   （密码框已被清空：""）
[2] 在密码框直接补打 "8"    → 依旧失败，失败后再次清空（追加陷阱已被消除）
[3] test01 + 12345678      → 已登录  登录成功：test01（u_20996175）
[4] 点「刷新档案」          → 已登录  档案已刷新（段位/积分/配置槽/战绩/未读全部渲染）
```

**用户操作**：浏览器按 `Ctrl+F5` 刷新一次（静态资源为 `no-store`，刷新即取到新前端），再用 `test01` / `12345678`（半角、无空格）登录即可；分册 §11 走查表已加第 17 步专门覆盖该场景。

## 6. 登记项（本批发现，未擅自扩大范围）

| # | 事项 | 处置 |

| R-1 | `DELETE`/`PUT` 等**非 GET 且带请求体**打到未知非 API 路径时，服务端可能返回 `400`（`connection: close`、无信封）而非 `404 unknown_endpoint`。根因：Node 的 http **客户端**对 `DELETE` 不发送 `Transfer-Encoding: chunked`，服务端解析器与后续字节错位（异步 handler 下暴露）。**实测 `publicDir` 为空时同样复现 → 与静态托管无关，属既有行为** | 本批**不修**（不在 F1 范围、且非前端契约）；已在 `tests/frontend/static-hosting.test.js` SH-4 注释登记并规避。建议后续登记进 `docs/security-backlog.md`（畸形请求健壮性） |
| R-2 | `public/**` 尚未纳入 `scripts/check-arch.js` 的分层登记（总纲 O-7 剩余部分）。本批以「单一出口/单一写入点/投影单一真源」的测试断言代偿 | 待 O-7 在后续批次裁定 |
| R-3 | 后端目前只托管 `public/`；`docs/tasks.md` §7 提到的 `/shared`、`/assets` 静态托管**未实现**（本批不需要：前端零第三方依赖、未使用美术表） | 后续需要时按总纲 §2.7 走决策 + 分册 |
| R-4 | 「忘记密码 / 免登录重置」不做（后端无该端点、无邮件设施） | 分册 §1 非目标 1 显式登记；若要做须先改后端契约 |
