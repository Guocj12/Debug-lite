## 6. 登记项（本批发现，未擅自扩大范围）

| # | 事项 | 处置 |
|---|---|---|
| R-1 | `DELETE`/`PUT` 等**非 GET 且带请求体**打到未知非 API 路径时，服务端可能返回 `400`（`connection: close`、无信封）而非 `404 unknown_endpoint`。根因：Node 的 http **客户端**对 `DELETE` 不发送 `Transfer-Encoding: chunked`，服务端解析器与后续字节错位（异步 handler 下暴露）。**实测 `publicDir` 为空时同样复现 → 与静态托管无关，属既有行为** | 本批**不修**（不在 F1 范围、且非前端契约）；已在 `tests/frontend/static-hosting.test.js` SH-4 注释登记并规避。建议后续登记进 `docs/security-backlog.md`（畸形请求健壮性） |
| R-2 | `public/**` 尚未纳入 `scripts/check-arch.js` 的分层登记（总纲 O-7 剩余部分）。本批以「单一出口/单一写入点/投影单一真源」的测试断言代偿 | 待 O-7 在后续批次裁定 |
| R-3 | 后端目前只托管 `public/`；`docs/tasks.md` §7 提到的 `/shared`、`/assets` 静态托管**未实现**（本批不需要：前端零第三方依赖、未使用美术表） | 后续需要时按总纲 §2.7 走决策 + 分册 |
| R-4 | 「忘记密码 / 免登录重置」不做（后端无该端点、无邮件设施） | 分册 §1 非目标 1 显式登记；若要做须先改后端契约 |
| R-5 | 无跨标签会话同步（B-11）：另一标签登出后本标签不自动失效，直到下一次请求 401 | 本批不做，已在分册 §8 登记 |
| R-6 | **`server/battle.js` 的 `REPLAYS` 是模块级注册表**，在单进程 runner（`--test-isolation=none`）下**跨测试实例共享**：本批 SH-5 初版用 `GET /api/v1/replay/r1` 断言 404，结果被同进程内其它用例创建的 `r1` 命中有 200 → 断言失败。已改用确定性 id（`r0` 永不出现）并补 `400 bad_replay` 动态路由校验 | 本批只改测试；该耦合本身是既有设计（`README-AI.md` 已登记"模块级 Map 无内建上限"），**建议后续回放批次一并处置**（如把注册表挂到 runtime 实例上） |
