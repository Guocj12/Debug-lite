## 缺口自查（五项按任务要求逐条）

① **bootstrap 时序（模块级 boot() 副作用）**：**结论——安全，但首跑 flake 需解释**。app.js 模块级 `boot()` 在测试进程首次 import 时自启动：node 全局 fetch 对相对 URL → undici **异步 reject**（"Failed to parse URL"，探针实证）→ `.then().catch()` 同步挂接消化 → resolve null，**无 unhandledRejection、不干扰并行测试**（F0 probe2 结论延续）；`store.dispatch('goto')` 无 effect 空转 ✓。全量套件多次运行稳定性：**首跑 gate 项 7 报 1 失败（当时与 npm test 并行运行两套全量）→ 此后 16 轮（cov×5 + gate×3 + 门禁式嵌套探针×8）复跑全绿**；并行复现探针（probe-flake 4 轮 + npm test 同时跑）结果待收尾（见实测定）；若再现，需 gate 输出失败明细（现 gate 只计数不打印用例名——P2-12 建议）。判 P2 登记，非 P1：无可复现路径、无泄漏面。
② **seed 回带在 box 场景的先后/幂等**：/box 响应 data.seed 整数 → onSeed 同步回调 → `seed/set` dispatch（先）；effect 随后 `box/done`（同步 dispatch，reducer 内 `r.data.seed || state.seed` 再写同值）→ 先 seed/set 后 box/done、同值幂等，**无竞争**；box/done onChange 落盘时 seed 已就位 ✓；唯一边角：`r.data.seed || state.seed` 对 seed=0 丢值（服务端保证 ≥1，防御登记 P2-11）。
③ **localStorage 双 key（state/logPrefs）一致性**：save 三次 setItem **非原子**——STATE 写成功、LOG/SEED 写失败 → load 只校验 STATE_KEY 的 schemaVersion，logPrefs/seed 半写不可察（P2-12）；结合 P1-5（key 分叉）修复后建议 save 顺序 STATE→LOG→SEED 且在任一失败时整体 remove 或返回 false 由调用方处理。当前批内无写失败路径（无配额模拟），判 P2。
④ **深拷贝 vs 结构共享（immutable 语义）**：initialState() 每次全新对象 ✓；reducer 浅合并下 **box/done 合并的 item 对象与 `gacha.lastResult.items` 共享同一引用**（探针 + 代码实证：`wh[bucket]=[...wh[bucket], ...items]` 复制数组不复制对象，lastResult=r.data 原引用）——视图若 mutate lastResult（如 F3 动画打标记）即脏仓库；`loadout/set`/`wh/replaced` 对 payload 直引。批内无 mutation 路径（纯函数 render 纪律），判 **P2**：建议 box/done 落 `lastResult` 用克隆（structuredClone 或 map 复制）或冻结纪律登记给 F3。
⑤ **toast 文案 action.type 前 20 字符**：全部 effect 类型名 ≤16 字符（最长 `loadout/validate`=16、`wh/disassemble`=16），**截断实际永不触发**；文案含英文业务码（`tier_locked`/`item_missing` 等）——用户可读性差、message 未展示，判 P2 轻量登记（建议 F3 错误映射表统一中文）。

### P1（必须当批修复）

1. **P1-1 仓库形状：前端扁平键 vs 后端 `{buckets:{…}}`（装配/拆卸 100% 失败）**。`initialState().warehouse` 用 `{role:[],skill:[],rolePlugin:[],skillPlugin:[]}`（扁平），而权威契约（interfaces.md §1 B18、api-wh.test 逐行、cli/index.js `wh.buckets`、`items.emptyWarehouse()`）为 `{buckets:{role:…}}`。探针实证（probe-shapes）：`items.assemble(扁平仓库, {targetUid:'item_1',…})` → **item_missing**（findItem 读 `wh.buckets`，扁平仓库找不到任何物品）——即 `box/open` effect 发出的 `st.warehouse` 使 **wh/assemble、wh/disassemble 每一个请求都失败**；且 `wh/replaced` 成功装入 `r.data.warehouse`（{buckets} 形状）后**状态形状翻转**，后续 box/done 对 `wh['role']`（undefined）展开 → TypeError（潜伏崩溃路径）。任务书"仓库沿用后端 buckets 形状"的登记理由与实现不符（实现是第三种形状）。**修复**：initialState/mergePersist/box-done 合并目标统一为 `{buckets:{…}}`（`wh.buckets[bucket]`），box/done 桶访问补 `|| []` 防御；store.test / f1-extra / persist 测试夹具（`warehouse:{role:[…]}` 等 6+ 处）同步改；persistFields/mergePersist 无需改形状名但 fixtures 变。
2. **P1-2 box/done items 形状：服务端返回数组、reducer 按分桶对象索引（开箱后仓库恒空）**。探针实证（probe-shapes）：`openBoxes({seed,tier:epic,times:3})` → `data.items` 为**数组**（`items[0].kind='skillPlugin'`，api-box.test L47 `items.length` 同证）；reducer `r.data.items[bucket]` 对数组取字符串键 → undefined → `Array.isArray` 假 → **永不合并**（实测：box/done 后四桶全空）。测试假数据（store.test `items:{role:[{uid:'r9'}]}`）与实现**同谋掩盖**。**修复**：box/done 改为遍历 `(r.data.items||[])` 按 `it.kind` 分桶追加（`b[it.kind]=[...(b[it.kind]||[]), it]`）；store.test 改用真实服务端形状（数组 + kind）断言合并，保留"items 缺失"守卫用例。
3. **P1-3 reducer 缺 §4.2 两行：`ai/compile`→compiling=true、`ai/run`→battle.running=true**。两 action 落入 default 原态返回——effects 已在本批实现，但"编译中/运行中"标志永不为 true（F5/F6 依赖）。**修复**：`case 'ai/compile': return {...state, aiDraft:{...state.aiDraft, compiling:true}}`；`case 'ai/run': return {...state, battle:{...state.battle, running:true}}`；f1-extra 补两行断言。
4. **P1-4 ai/run 请求体缺 tier**。spec §6.5：`POST /ai/battle {program,seed,tier,opponent}`；effect 发 `{ai, opponent, seed}`——服务端 `tier` 缺省 **mythic**（runner.js L83），段位门控意外宽松（低段位程序可跑高段位校验）。**修复**：加 `tier: st.tier` 一行 + 请求体断言（f1-extra 已记录 body 于 log，补断言即可）。
5. **P1-5 logPrefs 持久化 key 分叉：persist 写 `dl.v3.logPrefs`、util/log 引导读 `logPrefs`**。§4.3/§8 权威 key 为 dl.v3.logPrefs，§2.4 措辞为 localStorage.logPrefs（spec 内部矛盾）；实现各取一半 → F2 设置屏经 log/set 写的 logPrefs（经 SAVE_ON_ACTIONS→savePersist→dl.v3.logPrefs）**重启后引导不读取**（util/log L19 读 'logPrefs'），日志级别/通道设置全丢。**修复**：util/log.js 改读 `dl.v3.logPrefs`（持久层权威；util/log 属 F0 交付物，本批修 + F0 测试桩 key 同步改），并登记 spec §2.4 措辞漂移（文档同步 §10）。
