## 发现的问题

### P0

### P1（必须当批修复）

**P1-1（阻塞收口）restoreContext 对函数体内嵌套帧反查失败被丢帧 → T-AF-7「往返后继续执行结果一致」对合法程序违反**

位置：`server/ai/runtime.js`（帧路径生成 `fn:${stmt.name}` 于 238；restoreContext 反查 360-380）。

机制：函数体内任何**非顶层**帧（函数体 `seq` 帧的挂起子帧）路径带后缀——`fn` 内 `loop` 帧路径 `fn:f.s[0]`（kind=loop → 走 `nodeAtPath`，首段 `fn:f` ≠ `body` → 返回 null 被丢弃）；`fn` 内 `if` 分支 seq 帧路径 `fn:f.s[0].then`（kind=seq → `startsWith('fn:')` 后整段按函数名 findFunction(`f.s[0].then`) → 找不到 → 丢弃）。只有函数体最外层帧 `fn:f` 能正确按名反查。

复现（合法程序，A-3+A-5 组合形态，attack1 T1/T2；后附 pDeepRec E2 同因）：

```
var n = 0
function f { loop count 3 { action skill1 } }   ← 循环体含 action，D-101 合法
call f
action tail
```
- 基线行动序列：`skill1, skill1, skill1, tail, skill1, …`；
- 第 2 个 action 后 serialize（帧表 `["seq:body","seq:fn:f","loop:fn:f.s[0]","seq:fn:f.s[0].body"]`）→ restore → 后续序列变成 `tail, skill1, …` —— **循环剩余 2 次迭代被静默跳过**，往返后行动序列 ≠ 基线。

T2 同构（`fn f { if c { action a; action b } }`）：挂起在 `a` 后，往返后 `b` 永不再执行，直接出 `tail`。E2（pDeepRec 深层递归）路径一致（帧表含 5×`seq:fn:r.s[0].then` 被丢），仅因窗口内行动恰好相同而表面通过——n 轨迹与深度语义已偏离。

影响面：引擎战斗路径（runAiBattle）不经过 serialize/restore，**无线上影响**；但 serializeContext/restoreContext 是 B16 头条交付（interfaces §4.5 冻结 AiContext 可序列化 + T-AF-7 硬不变量），且 B14 P2-3「fn:name 路径 B16 落地统一」正应在此兑现——现状只统一了顶层帧。**必须当批修复并在 B16.md 登记回归**。

修复方向（任选其一，建议前者）：① restoreContext 对 `fn:` 前缀路径先取首段函数名 findFunction，余段在函数体内按 nodeAtPath 同规则继续解析（seq 帧与 loop 帧统一走该逻辑）；② 运行时函数体内帧路径改为 AST 规范路径（`body.s[i].body…`，函数体即 `nodePathOf` 的 `.body` 段），则全部路径可由 nodeAtPath 直接反查，trace 路径亦与前端高亮规范统一（B14 P2-3 彻底落地）。

必须配套回归（断言行动序列 == 基线、且补断言变量轨迹）：① fn 内 count 循环挂起往返（attack1 T1 形态）；② fn 内 if 分支多语句挂起往返（T2 形态）；③ pDeepRec 深层递归挂起往返（断言 n 递减轨迹一致，防 E2 式假阴性——窗口需长于栈内剩余层级）。

### P2 登记（不阻塞，建议当批或 B17 处理）
