### P1（必须当批修复）

**P1-1（I-10a 类别校验漏第三态 → 客户端可触发 500）`assemble`/`disassemble` 对「目标存在但非 role/skill（如把插件当目标）或目标缺 slots 数组」抛 TypeError 崩溃 → HTTP 500 internal_error，应返回业务拒绝码**

位置：`server/core/items.js:304-308`（assemble）/`:340-341`（disassemble）。①类别匹配只有 `role`/`skill` 两分支：`target.kind === 'rolePlugin'`（或任何非 role/skill kind）时两检查均放行，随后 `target.slots[slotIndex]` 对 undefined 抛 `TypeError: Cannot read properties of undefined (reading '0')`；拆卸同款（`target.slots` 缺失）。该输入**真实可达**：CLI `wh assemble --item p1 --slot 0 --plugin p2`（把插件当目标，正常玩家误操作形态）→ 500；真实 socket 实证（probe-http ③）双端点均 `500 internal_error`，api.err 记录 2 条。I-10a 语义：「插件 kind 与**目标模板**匹配」——插件不是模板，任何插件 → 插件目标均属类别不匹配，应 **409 slot_type_mismatch**（装配）/ **404 slot_empty 或 slot_empty 口径**（拆卸，槽位不可用）；当前返回 500 = 契约偏差（非内部 bug 抛穿——是**未校验的客户端输入**，与 B17 认可的「TypeError 抛穿不吞 bug」有本质区别）。

修复（各一行级）：
- assemble：kind 检查前补 `if (target.kind !== 'role' && target.kind !== 'skill') return { ok:false, code:'slot_type_mismatch', message:'目标不是角色/技能模板' };`
- 双端点：槽取值加数组守卫 `…&& Array.isArray(target.slots) ? target.slots[slotIndex] : null`（防手工删 slots 的角色/技能目标复现崩溃）。
- 必配回归：core 一条（插件作目标 → slot_type_mismatch，拆卸 → slot_empty）+ HTTP 一条（真实 socket 断言 409/404 而非 500）。

**P1-2（仓库结构防御缺口）`findItem` 对「桶值非数组」抛 TypeError → HTTP 500，与批内「不可序列化 → 兜底」防御承诺相悖**

位置：`server/core/items.js:285`。`warehouse.buckets` 为字符串（`{buckets:'abc'}`）或任一桶值非数组（`{buckets:{role:'x'}}`）时，`Object.values` 产出标量元素，`(list || []).find` 对字符串调用 → 抛 TypeError（probe-http ④ 实证：真实 socket 500 internal_error + api.err 记录）。批内已承诺「环/不可序列化 → 兜底空仓库」的降级意图（cloneWarehouse catch 只防 JSON 失败，可序列化但结构畸形穿过兜底）；D-123 客户端状态权威模型下畸形文件是必然输入形态。修复一行：`if (!Array.isArray(list)) continue;`。必配回归：core 一条（`{buckets:'abc'}` → item_missing 不抛）+ HTTP 一条（400/409 而非 500）。
