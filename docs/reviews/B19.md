### P1（必须当批修复）

**P1-1（I-12b 结构错误输入 → 客户端可触发 500；B18 P1-1 同型复现）`validateLoadout` 在「wh 存在且 ld.role 存在」时无条件 `skills.forEach`，skills 非数组（如 `'zzz'`）或缺失时 `skills=null` → `TypeError: Cannot read properties of null (reading 'forEach')` → HTTP 500 internal_error**

位置：`server/loadout.js:45`（refs 收集块，`if (wh && ld.role)` 内）。前置结构检查把 skills 归一为 `Array.isArray ? : null`（`:32`），但 refs 块未复用该守卫。输入**真实可达**：POST /loadout 与 POST /panel `{loadout:{role:{kind:'role',…}, skills:'zzz', ai:{…}}, warehouse:{…}}` → 真实 socket 实证**双端点均 500 internal_error + api.err**（probe-http [2][3]；应 409 loadout_invalid）。这是 B18 P1-1（「目标 kind 第三态缺失 → TypeError 500」）同型 —— B18 已修复并建立「未校验客户端输入不得崩溃」的防御姿态，findItem 畸形桶防御延续了（probe ⑧b/c 全过），唯独 refs 收集的 skills 迭代漏网。

修复（一行级）：refs 收集整体移入 `if (errors.length === 0 && wh)`（结构与门控段同构的 fail-fast —— skills 到此时必为长度 3 数组），或最小改 `(skills || []).forEach`。必配回归：core 一条（skills='zzz' / 缺失 + warehouse → `{ok:false}` 不抛）+ HTTP 一条（双端点断言 409 而非 500）。

**P1-2（T-PB-8 全局唯一性在 loadout 层缺兜底 → 面板词条双计错误值）同一 pluginUid 被 loadout 多处引用（同角色双槽 / 跨角色与技能）且 equipped=true → 校验放行，buildPanel 双计词条**

位置：`server/loadout.js:42-53`（refs 循环只查存在 + equipped）。实证：`role.slots[0]`/`role.slots[1]` 同 'pa'（equipped=true）→ validateLoadout `ok=true`、HTTP 200；buildPanel atk=round(20×1.20)=**24**（应 22，+10% 词条被聚合 2 次）；跨目标（role.slots[0] + skills[1].slots[0]）同样放行（probe-http [4][5]）。I-12d「无悬挂引用」只约束存在性；T-PB-8「同一插件不可同装两处」是装配 API 强制的不变量（plugin_equipped），合法流程无法自产生双引用 ⇒ 双引用 ≡ 注入不一致状态 —— 恰是 B18 P2-6 ② 明示「由 B19 T-PB-9 承担兜底拒绝」的形态（**B18 登记的兜底承诺未兑现**）。且双计直接污染"最终面板"数值（B22 战斗的输入来源）。

修复：refs 收集中对 uid 建 Set，重复 → 错误 `{where, code:'loadout_invalid', message:'插件重复装配: <uid>'}`（覆盖同目标与跨目标一切形态）。必配回归：unit 一条（双引用 → 拒绝）+ HTTP 一条（409，/panel 同断言）。

**P1-3（无 warehouse：引用校验空转 + /panel 返回非最终值，无任何标记）带装配引用的 loadout 缺 warehouse → T-PB-9/I-12d 校验整体跳过（含悬挂引用放行），面板返回纯 base 数值（atk=20 而非 22）**

位置：`server/loadout.js:42`（`if (wh && ld.role)` —— 无 wh 时 refs 块整体跳过）+ `buildPanel`（wh=null → findItem 全空 → 零词条）。实证链：validateLoadout(带 pluginUid 引用, 无 wh) → `ok=true`；悬挂引用 'ghost' 无 wh → `ok=true`（T-PB-9「无悬挂引用」验收点空转）；POST /panel 无 warehouse → 200 + atk=20/hp=100（probe-http [6]）；**CLI 官方支持的「裸 loadout 文件」路径即静默触发**（`panel --loadout <裸文件>` → exit=0 且 atk=20，probe-cli [2]）。「最终面板」契约（interfaces §2）返回非最终值且无标记 = 误导性输出；而 /loadout 作为校验服务对无法校验的状态静默放行，违背该批自身定位（B18 P2-6：T-PB-9 承担注入态兜底）。
