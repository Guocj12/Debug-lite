## 发现的问题

### P0

无。

### P1（必须当批修复）

**P1-1（核心交付语义偏离）`rollQuality` 截断品质池后未按 dropRates 重归一加权：残量整体落入池顶档，rare 档分布偏差 11.3pp**

位置：`server/core/items.js:46-60`。`const total = pool.reduce((a,t) => a + rates[t], 0)` 计算后**从未使用**——比较仍为原始累加 `acc += rates[t]; if (v < acc)`。当 `total < 1`（截断时）v ∈ [total, 1) 的区间全部落入尾部兜底 → 池顶档实际概率 = rate + (1 − total)。这是「截断不归一」模型，与本批交付要求「**截断品质池后按 dropRates 重归一加权**」（D-122/RK-5）不符；未用的 `total` 即未完成重归一改造的物证。

独立大样本实测（N=400000/档，`.review-b17/distribution.js`）：

| tier | 档 | 实测频率 | 重归一期望 | 偏差 |
|---|---|---|---|---|
| rare | common | 54.94% | 66.27% | −11.33pp |
| rare | rare | 45.06% | 33.73% | **+11.33pp** |
| epic | epic | 17.05% | 12.63% | +4.42pp |
| legendary | legendary | 5.08% | 4.04% | +1.04pp |
| common / mythic | — | 100%/全池 | 同 | 0（天然无偏差） |

影响面：① 段位掉落池门控（本批头条）的概率语义偏离——rare 段玩家拿到 rare 品质的概率比设计高出 1/3；② 同一机制已被 B25（段位→奖励品质，T-RK-4/tierReward）预定复用，若不修将蔓延至排位奖励；③ 现有测试全绿原因：B17-2 只断言**成员资格**不断言**分布**（敷衍黑名单第 5 项「无大样本统计」的盲区形态）。

修复（一行 + 两条回归）：
- `items.js` 比较改为 **`if (v < acc / total)`**（或 `v * total < acc`）；尾部兜底保留（v=1 stub 防御路径 IT-3c 语义不变）。无 tier 时 total=1.0 → 行为与 B3 完全一致，无回归面。
- 必配回归：① rare 档 **≥10000 样本**分布断言：common≈66.3%、rare≈33.7%（对重归一期望 ±2pp 容差，T-IT-1 同款口径）；② 顺手补「tier 非法 → 全池」断言（`rollQuality(rng,'diamond')` 不抛且落在全池）——交付承诺「tier 缺省/非法 → 全池」目前零断言，且补后 items.js 分支 86.67 → ≥90（差分实测 92.06）。

### P2 登记（不阻塞，建议当批或 B18 处理）

1. **P2-1（seed 上界回绕）** `box.js` 只校验 `seed ≥ 1` 整数，未设上界：seed=4294967297（2^32+1）经 `normalizeSeed >>> 0` 回绕成 1——内容与 seed=1 完全相同但响应回带原值（实测 boxseed ④）。同值重放可复现（回带原值），但跨 seed 别名可能误导诊断。建议校验 `seed ≤ 0x7fffffff`（与 crypto.randomInt 生成上界一致）或文档声明支持域。
2. **P2-2（409 触发条件文档化）** 当前数据各段位 kind 池恒非空 → HTTP 层 409 tier_locked 真实数据不可达（防御路径）；T-AP-3 已按 helper 级（B17-5 stub）覆盖。建议 interfaces.md §2 box 行注明「409 = 门控后掉落池为空（当前数据不可达，防御路径）」，与 box.js 头注对齐。
3. **P2-3（非法 tier 分支零断言 + 分支缺口）** 「tier 非法 → 全池」属交付承诺行为，但无测试（box 层先拒使生产不可达）；同时是 items.js 分支 86.67 缺口的组成部分。补 1 条断言（probe-A 形态）即可提回 ≥90（差分实测）。
4. **P2-4（uid 语义落文档）** 同 seed 复现=内容级（uid 进程级自增、跨调用/跨进程不同）已由测试注释登记，但接口文件未写。B18 仓库开工前建议 interfaces.md 明确「物品 uid 仅进程内唯一（服务重启后重新计数）；同 seed 复现均为内容级」——仓库区分同 seed 双开物品依赖进程内单调 uid，成立无冲突（缺口①预判结论）。
5. **P2-5（缺省 tier 口径）** API 层缺省 `tier='common'`（box.js）而 core `openBox` 缺省 `'mythic'`（B3 兼容）——interfaces.md §2 box 行未写明缺省值。建议注明「tier 缺省 common」（CLI 示例已显式 common，无歧义问题，纯文档补缺）。
6. **P2-6（L1 模块 ICD 补登）** `server/box.js` 已进 check-arch 与 git，但 tasks.md §2.1 L6 行仍为 `server/index.js · server/runner.js · cli/`（漏 box.js），interfaces.md §1 模块表亦无 box.js 行（导出 openBoxes/BOX_TIMES_MAX）——L1「先冻结接口」要求模块 ICD 全量，顺手补登。
7. **P2-7（超限 body 500 容忍）** readBody 超 1MB reject 被 createHandler catch 成 500 internal_error（非 413/400）——P0-8 遗留、B16 各 POST 端点同款，box 端点同受影响；登记不修（统一后续批次处理）。
8. **P2-8（校验顺序说明项）** openBoxes 按 tier→times→seed 顺序校验，多参数同时非法时返回首个错误码；契约未声明顺序——与既有端点（ai 路由）同款，登记为既有约定，不改。
