### F5-A（P2）配置编辑器的 `ai-pick` 把**库内草稿**当作普通候选列出且**无任何标记** ⇒ 用户可选择、保存时才 409（"点了才告诉你不行"）

- **位置**：`public/format.js:790-794`（`aiCandidatesOf` 只投影 `{aiId,name,program}`，**不含 `status`**）＋ `public/format.js:1077-1110`（`aiPickModal` 的行按钮标签 = 名字，**不显示正式/草稿，也不置灰**）＋ 判据在 `server/account.js:878-884`（`draftAiDetails`，409 `ai_is_draft`）
- **主张**：D-172④ 把"草稿不能被出战配置引用"定为**硬护栏**，但**前端唯一的候选来源没有携带 `status`**，于是配置弹窗里草稿与正式条目**看起来完全一样**、都可点。用户必须"选中 → 保存 → 吃 409 → 读提示 → 回弹窗换一个"才能知道。`06-ai-editor.md` §1 「本批要做」写着"不得选中草稿"，实现只做到"不得保存"（服务端侧）——**候选面缺一条投影**。
- **反例/复现**（`probe-f5-pick.js`，真实 HTTP + 浏览器同构 harness）：
  ```
  草稿创建: 200 draft
  ai-pick 候选数 = 2 含草稿？ true
  候选对象键 = ["aiId","name","program"]        ← 没有 status
  选中草稿后弹窗 = {"kind":"config","slotId":"slot1"}
  保存引用草稿 HTTP = 409 ai_is_draft
  config-save 后 notice = "草稿 AI 不能被出战配置引用（字段：aiId）"   ← 文案可读，但为时已晚
  ```
  代码级复核：`aiPickModal` 的 `rows[].text` 全是 `''`，唯一信息是 `buttons[0].label = items[i].name` ⇒ **屏幕上没有任何"草稿"字样**（`probe` 实测 `弹窗里出现「草稿」字样 = false`）。
- **严重度**：**P2**。不是数据错误（服务端 409 兜住，草稿**不可能**进入任何配置），但是**用户可见的可用性缺陷**：① 主要流程"去配置里绑定刚写好的 AI"在草稿态必然失败一次；② 用户可能误以为"我的 AI 坏了"。
- **处置建议**（精确到行）：
  1. `public/format.js:791-793`：`aiCandidatesOf` 的投影加一项 `status: pick(ai, 'status') === 'draft' ? 'draft' : 'ready'`（`format.js:2087` 已有同口径的 `aiItemStatusText`，可直接复用常量口径）；

## 9. 交付后用户实测反馈与修复（父代理，2026-09-25）

> 与 `D-163` 同类：**用户拿到界面后实测**提出的问题。**不新增决策编号**（属 F5 自身 UI 范围、不触碰
> `/api/v1` 契约，故不走 §2.7），只更新分册 §3.2 与本节。

**用户原话**：「AI 编辑界面几乎看不出各逻辑之间的关系。添加简单的缩进，来保证能看出各循环、分支等之间的关系（类似 python 缩进即可）。」

**根因（读码 + 探针实测；两条，第二条才是主因）**：

1. **缩进字符层级感极弱**：`treeLines` 的 `depth` 原本用全角空格 `U+3000` 逐层拼接（码点实测 `3000,3000,…`）——
   字符确实在，但在浏览器默认字体下几乎不可辨；
2. **（主因）渲染顺序把结构拆散了**：`render.js` 的旧路径是 `linesHtml(vm)` **一次性输出所有文字行**，
   随后才 `rowsHtml(vm)` 输出所有行；而「程序结构」标题在 `lines` 里、程序树在 `rows` 里 ⇒ **标题与树被拆到
   屏幕两端**；「当前节点」标题与它的字段/选项按钮同样各归各块。这不是缩进问题，是"标题 ↔ 内容"配对丢失。

**修复**：

| # | 改动 | 位置 |
|---|---|---|
| 1 | 新增 **有序区块** `vm.blocks`（`{kind:'lines'\|'rows'\|'fields'\|'buttons'\|'textarea'}`）：按声明顺序就地渲染，标题紧跟其内容。**未声明 `blocks` 的屏走原路径（渲染结果逐字不变）** | `public/render.js`（`blocksHtml` + `render` 分支） |
| 2 | 编辑态改用 blocks：名称输入 → 档案信息 → 校验错误（标题+逐条）→ **程序结构（标题+图例+树）** → 当前节点表单（标题+说明+字段+选项按钮）→ 表达式槽/语句块（各自标题）→ 插入/替换/结构按钮 → 导入区 → 底部操作 | `public/format.js` 的 `aiEditViewModel` |
| 3 | 缩进改为**可见导轨** `│ `（每层一个）；**隐式主循环前移到第一行**、其余语句缩进在它里面（Python 式）；分支/循环体标签行 + 其下再缩进一层 | `public/format.js` 的 `aiTreeIndentOf` + 树区块 |
| 4 | 新增图例行（说明 `│ `、`那么/否则/循环体`、`← 当前选中` 的含义） | `public/format.js` 的 `AI_TREE_HEADING`/`AI_TREE_LEGEND` |

**修复后的实际呈现**（探针原文）：

```
while(true) 引擎隐式主循环（不可删除）　← 当前选中
│ 循环 计次 3 次
│ │ 次数：3
│ │ 循环体：
│ │ │ 如果 (self.hp < 30)
│ │ │ │ 条件：(self.hp < 30)
│ │ │ │ 那么：
│ │ │ │ │ 动作 defend
│ │ │ │ 否则：
│ │ │ │ │ 动作 move_right
│ 动作 wait
```

**回归**：新增 **AE-14**（`tests/frontend/ai-editor-flow.test.js`）——断言 ①编辑态必须声明 `blocks`；
②「程序结构」标题块的**下一个区块必须就是树**；③隐式主循环在树的第一行且不带缩进；④顶层语句 1 层导轨、
循环体内 `if` 3 层、`那么`/`否则` 同层、分支内语句比标签再深一层且两分支同层；
⑤渲染后 `标题 < 树 < 当前节点表单` 的**顺序断言**；⑥未声明 blocks 的屏（登录屏）不受影响。
另同步修正 AE-5 的读法（编辑态文本现在分布在 `blocks` 里）。

**复跑**：`ai-editor-flow.test.js` **10/10**；全量 `npm test` = **1136 通过 / 0 失败**；`npm run gate` = **9 PASS / 0 FAIL / 0 PEND**；`npm run e2e` = **22/22**。
