## 3. 环境与硬约束（已实测，别重复踩）

1. **`node --test` 在本沙箱会失败**（runner spawn 子进程 + 管道 stdio → `EPERM: spawn`）。
   → 全量测试入口**必须**用：`node --test --test-isolation=none "tests/**/*.test.js"`（**glob 必须是 `tests/**/*.test.js`**；`package.json` 的 `npm test` 即此口径。传目录会报 `ERR_UNSUPPORTED_DIR_IMPORT`）
2. **脚本内部禁止 `child_process`**（同样 EPERM）→ `scripts/gate.js` 必须在**单进程内联**执行全部检查。
3. **失败用例退出码必须是 1**（已实测成立），门禁不得被"静默通过"。
4. **命令的工作目录必须已存在且在 `F:\Game\Debug-lite` 内**，否则 shell 无法启动。
5. **依赖白名单：无**（2026-09-16 复核）。运行时**零依赖**（`node:http`），测试与日志**零依赖**（`node:test` + 自研 `shared/log.js`）；`express` 虽在历史白名单中但**从未引入**。P6 才考虑前端依赖。
6. `legacy/` 是已归档的 v2 代码，**只读参考，不要修改、不要复用其资源**。
7. **`npm run demo` 与 `npm run play` 均可执行**（2026-09-16 更新：`scripts/demo.js`、`scripts/play.js` 均已落地并实跑通过；`play` 为离线文本闭环，无需 `npm start`）。**门禁现状**：四项门禁全绿；若中途因**并行改动**出现瞬时红，先看 `docs/progress.md` §3.4 的复测说明再判断是不是你引入的。

## 5. 门禁 `npm run gate` 必须真的是门禁

`tasks.md` §3.4 定义了 9 项，**必须全部真实生效**（不是打印"通过"）：

1. 静态：无 `Math.random`/`eval`/`new Function`（core/ai）
2. 静态：`server/core/**` 无 `console.*`
3. 架构依赖方向检查（无反向/循环依赖、core 无 IO 依赖）
4. 数据表 schema 校验（含 `regen`/`slotWeights`/`unlockTier`/`costDeltaByTier`/`falloff`/`bulletLevel`，且**不得出现 `bulletSpeed`**）
5. 文档 ↔ 数据一致性（11 角色模板 / 10 技能模板 / 5 品质 / 插件与 `items-data` 表格逐条对齐）+ **D 编号落点检查**
6. 日志事件命名规范 + 战斗数值未硬编码
7. 全量测试（单进程 + 覆盖率：`core`/`ai`/`shared`/`cli` 行 ≥90%、分支 ≥85%、函数 ≥90%）
8. 日志冒烟：`trace` 跑一场，断言关键事件齐备、`cid` 链路可追，且**结果与 `silent` 级逐帧一致**
9. 接口冒烟：同进程 `listen(0)` 起服务 → 走 `/api/v1` 关键端点 → 跑一次**CLI 闭环**

**门禁失败只能通过修代码/修测试解决**；禁止放宽阈值绕过（阈值调整属变更控制，需单独 commit 并说明）。

## 6. 数值必须机器复算（本项目最重要的一条经验）

设计阶段的教训：**手算的数字会错**。因此：
- 任何出现在测试断言、`battle-config.json`、文档示例里的数值，都必须有一个**可复跑的脚本**算出（`node scripts/xxx.js` 或测试内的计算），不靠脑算。
- `docs/examples/*` 与 `docs/battle-walkthrough.md` 里的数值就是**期望值**：实现必须能复现它们（同 seed / 同输入 → 同输出）。
- 若实现算出的值与文档不符：**先怀疑文档**（回去查 `decisions.md` 的对应 D 编号），确认文档错了就**问我**再改文档；不要偷偷改断言。
