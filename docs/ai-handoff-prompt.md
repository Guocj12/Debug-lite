# 实现期交接提示词（交给新 AI）

> 用法：把本文件**整篇**作为新会话的第一条消息内容（或说「读 `docs/ai-handoff-prompt.md` 并严格执行」）。
> 本项目已完成**设计阶段**，现在进入**编码阶段**。请按本提示词工作，不要自由发挥流程。

---

## 0. 你的角色与目标

你是 Debug-Lite v3 的**实现者**。目标：按 `docs/tasks.md` 的批次表，从 **P0-1** 开始逐批实现，**每批都跑通全量门禁并单独提交**，直到 P5 完成（P6 前端延后，本轮不写 UI）。

**一次只做一批**。做完 → 跑门禁 → 提交 → 报告 → 再做下一批。禁止一次性写完多个批次。

## 2. 铁律（违反任何一条即为该批未完成）

取自 `docs/tasks.md` §0，最容易被违反的几条在此强调：

- **L1 先冻结接口再写实现**：每批先更新 `docs/interfaces.md`（本文件在 P0-7 创建），再写契约测试，最后写实现。
- **L2 每批一个 commit**：禁止跨批次/跨模块混提。
- **L3/L4 每批全量门禁 + 测试可追溯**：每个用例必须归属 `tasks.md` §3.2 的某个测试点编号。
- **L5 禁止敷衍测试**：见 `tasks.md` §3.3 黑名单（只断言 truthy、无边界值、无失败路径、`skip`/`todo` 等一律打回）。
- **L9 机制在代码、数值在表**：所有战斗数值来自 `server/data/battle-config.json` 等数据表，**禁止硬编码**。
- **L11 纯函数内核**：`server/core/**` 禁止 IO、`Math.random`、`eval`、`console.*`；随机与日志一律**注入**。
- **L12/L13 日志是合同**：新增计算路径/跨系统调用**同批**补日志事件与断言（覆盖矩阵见 `tasks.md` §4.6）。
- **L14 接口自足**：新能力必须能通过 `/api/v1` 或 CLI 触达，否则视为未完成（本轮不写前端）。
- **L17 文档工具纪律**：**禁止用 PowerShell 5.1 的 `Get-Content`/`Set-Content` 读写中文文档**（曾导致整文件双重编码损坏，无法恢复）。改文档用文件工具或 Node（UTF-8 无 BOM）。

## 3. 环境与硬约束（已实测，别重复踩）

1. **`node --test` 在本沙箱会失败**（runner spawn 子进程 + 管道 stdio → `EPERM: spawn`）。
   → 全量测试入口**必须**用：`node --test --test-isolation=none tests/*.test.js`
2. **脚本内部禁止 `child_process`**（同样 EPERM）→ `scripts/gate.js` 必须在**单进程内联**执行全部检查。
3. **失败用例退出码必须是 1**（已实测成立），门禁不得被"静默通过"。
4. **命令的工作目录必须已存在且在 `F:\Game\Debug-lite` 内**，否则 shell 无法启动。
5. 依赖白名单：`express`（P0）。测试与日志**零依赖**（`node:test` + 自研 `shared/log.js`）。P6 才装前端依赖。
6. `legacy/` 是已归档的 v2 代码，**只读参考，不要修改、不要复用其资源**。

## 4. 每批的固定节拍（10 步，缺一步该批不算完成）

1. **规格**：从文档摘出本批接口清单 + 对应 `tasks.md` §3.2 测试点编号 + §4.6 日志事件行。
2. **冻结**：更新 `docs/interfaces.md`（签名/结构/API/CLI 契约/日志事件名/D 编号落点）。
3. **先红**：写契约测试，**确认失败**（证明测试有效）。
4. **实现**：只做本批范围；计算路径与跨模块调用**同批带日志**。
5. **接口自足**：接进 `/api/v1` 与 CLI，补 T-AP-*/T-CLI-* 测试。
6. **绿**：补单元/集成/日志覆盖测试，直到 `npm test` 全绿（含覆盖率阈值）。
7. **全量门禁**：`npm run gate` 全绿；`npm run demo` 正常。
8. **独立审查**：另起一个**干净上下文**的 agent，用 §7 的审查提示词对本批 diff 做对抗式审查，结论写入 `docs/reviews/BXX.md`；P0/P1 级问题**当批修复**。
9. **提交**：一个批次一个 commit，消息含接口清单与测试证据，例如
   `B07 bullets: 生成/连续碰撞/等级抵消 (+18 tests, core 93.2%/branch 87%, 日志 7/7, API 2)`
10. **记录**：更新 `docs/tasks.md` 的批次状态与 `docs/progress.md` 的待办勾选。

## 5. 门禁 `npm run gate` 必须真的是门禁

`tasks.md` §3.4 定义了 9 项，**必须全部真实生效**（不是打印"通过"）：

1. 静态：无 `Math.random`/`eval`/`new Function`（core/ai）
2. 静态：`server/core/**` 无 `console.*`
3. 架构依赖方向检查（无反向/循环依赖、core 无 IO 依赖）
4. 数据表 schema 校验（含 `regen`/`slotWeights`/`unlockTier`/`costDeltaByTier`/`falloff`/`bulletLevel`，且**不得出现 `bulletSpeed`**）
5. 文档 ↔ 数据一致性（11 角色模板 / 10 技能模板 / 5 品质 / 插件与 `items-data` 表格逐条对齐）+ **D 编号落点检查**
6. 日志事件命名规范 + 战斗数值未硬编码
7. 全量测试（单进程 + 覆盖率：`core`/`ai`/`shared`/`cli` 行 ≥90%、分支 ≥85%、函数 ≥90%）
8. 日志冒烟：`trace` 跑一场，断言关键事件齐备、`cid` 链路可追，且**结果与 `silent` 级逐帧一致**
9. 接口冒烟：同进程 `listen(0)` 起服务 → 走 `/api/v1` 关键端点 → 跑一次**CLI 闭环**

**门禁失败只能通过修代码/修测试解决**；禁止放宽阈值绕过（阈值调整属变更控制，需单独 commit 并说明）。

## 6. 数值必须机器复算（本项目最重要的一条经验）

设计阶段的教训：**手算的数字会错**。因此：
- 任何出现在测试断言、`battle-config.json`、文档示例里的数值，都必须有一个**可复跑的脚本**算出（`node scripts/xxx.js` 或测试内的计算），不靠脑算。
- `docs/examples/*` 与 `docs/battle-walkthrough.md` 里的数值就是**期望值**：实现必须能复现它们（同 seed / 同输入 → 同输出）。
- 若实现算出的值与文档不符：**先怀疑文档**（回去查 `decisions.md` 的对应 D 编号），确认文档错了就**问我**再改文档；不要偷偷改断言。

## 8. 遇到新歧义怎么办（不要自行发明规则）

实现时一定会遇到文档没写死的边界。处理流程：

1. 在 `docs/examples/README.md` §4 以 **`V-x`** 编号登记该子项（问题、出处、你的建议默认值）。
2. **停下来问我**（一条消息把该批遇到的 V 项一次列全，附你的建议）。
3. 我拍板后，写入 `docs/decisions.md`（新 `D-xx`）+ 同步受影响的 `systems/*`、`examples/*`、测试点，**然后再继续实现**。

**禁止**：为了让测试变绿而自选一个语义并写进代码；禁止改 `decisions.md` 里已冻结的条款（那是最高权威，只能由我确认后修改）。
