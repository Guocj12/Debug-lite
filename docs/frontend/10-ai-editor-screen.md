# 10 · AI 编辑屏（`ai_editor`）界面规格 —— 方案 A

> 用户 2026-10-18 裁决：「选方案 A」「左侧节点库中节点可以按类型展开/收起」
> 「树可向任意方向拖动视图、可放大缩小」「节点可拖动进程序树，自动缩进、自动吸附，
> 拖动时显示即将落到的位置预览」「点击空白收起右侧详情，点节点再展开」
> 「依旧编辑器实现不了的先改编辑器」。
>
> 本文是**实现规格**（元素 id / 坐标 / 状态键 / 算法 / 失败路径）。
> 坐标是**起点**：用户之后在布局台里手动微调，以 `tools/layout/layout-bundle.raw.json` 为准。
>
> 现状（改前）：`public/screens.js` 里 `ai-editor` 的 `layout: null` ⇒ 走**文字版**渲染
> （`format.js` 的 `aiBlueprintViewModel`）。本屏目标是把它换成布局表驱动。

## 3. 状态键（引擎新增可声明）

现在 `layout-engine.js` 把 `WHEN_KEYS` **硬编码**成 3 个。本屏需要 12 个，所以改成
**布局表可声明**：`bundle.stateKeys: ["aiSel", …]`，引擎校验时用 `DEFAULT ∪ bundle.stateKeys`。

| 键 | 取值 | 用途 |
|---|---|---|
| `aiSel` | 地址字符串（`body[0].then[1]`）或 `''` | 选中行按下态 |
| `aiDetail` | `1` / `0` | 参数栏显隐（0 ⇒ 树变宽） |
| `aiCanUndo` / `aiCanRedo` | `1` / `0` | 撤销/重做按钮显隐 |
| `aiPat`（每类一个） | `1` / `0` | 该分类是否展开 |
| `aiP1` / `aiP2` / `aiP3` | `1` / `0` | 三个选项槽是否显示 |
| `aiPNum` | `1` / `0` | 数值行是否显示 |
| `aiDropY` | 数字字符串 | 插入预览线的 y；空 = 不显示 |
| `aiPreset1..4` | `1` / `0` | 模板按钮显隐 |
| `aiTreeW` | 数字字符串 | 树宽度（980 / 616），供 `rectFrom` |

## 4. 交互规则

### 4.1 平移与缩放（树区）

| 操作 | 行为 |
|---|---|
| 在树区**空白**处按下左键并移动 ≥4px | **平移视图**（映射到容器的 `scrollLeft/scrollTop`，delta 取反） |
| 在树区**空白**处按下左键、移动 <4px 后松开 | 视为**点击空白** ⇒ 收起详情 + 取消选中（R6） |
| 滚轮 | **缩放树**（不按 Ctrl，用户 Q5）：40%~200%，步进 10%；以**指针位置为锚点**缩放（缩放后指针下的内容不跑） |
| 滚轮 + 已选中行 | 同上，不改变选中 |
| 双击空白 | 缩放回到 100%（便利项） |

**缩放实现方式（刻意选择）**：树行是**纯文字行**，所以缩放 = **按 zoom 放大 行高 / 缩进 / 字号**，
而不是 `transform:scale()`。理由：变换后浏览器不知道内容真实尺寸，滚动条会算错（这正是引擎
`grid.autoHeight` 当初要解决的问题）；而文字缩放**不失真、滚动条正确**。代价：没有亚像素平滑
过渡（可接受，树里没有图片）。

> 若将来树里出现图片素材，再补 `transform` 方案 + 外层占位块（记录在 §7 R-3）。

### 4.2 选中与详情

| 操作 | 行为 |
|---|---|
| 点树行 | `aiSel = 该行地址`；`aiDetail = 1`（自动展开参数栏） |
| 点空白 | `aiSel = ''`；`aiDetail = 0`（收起；**高亮一并消失**，用户 R6） |
| 点参数栏外（树区） | 同上 |
| 切换选中 | 参数栏内容换成新节点；面板保持展开 |
| `Del` / `Backspace` | 删除选中节点（与参数栏「删除此节点」等价） |

**详情收起时树变宽**：`aiTreeW = aiDetail ? 616 : 980`，由 `rectFrom` 应用到 `ai_tree`/`ai_tree_list`。

### 4.3 从节点库拖入程序树（核心）

用户 Q7 + 补充：「拖到两个节点之间 = 插入其间；拖到节点上 = 放进它的槽位；
放不进槽位 = 取消。**如果块下方既可算块内又可算块后，要按缩进位置判断**；
找最近的可插入位自动吸附并高亮；附近没有可插入位则取消。」

**规则 1（只在按住并移动后进入拖动态）**：左键按下节点行，移动 ≥4px 才进入拖动；
<4px 松开 = 普通点击（`ai-node-append` 追加到根末尾）。

**规则 2（候选插入位）** 拖动开始时，把所有**可插入位**列成候选，每个候选带一个**锚点 (x, y)**：

| 候选类型 | 锚点 x | 锚点 y |
|---|---|---|
| 「插到第 i 行之前」（同级） | `depth(i) × 16` | `top(i)` |
| 「插到第 i 行之后」（同级） | `depth(i) × 16` | `bottom(i)` |
| 「追加到 (节点 N, 槽 s) 末尾」 | `(depth(N)+1) × 16` | 该槽最后一个子行的 bottom（空槽 ⇒ 槽头行 bottom） |

**规则 3（类型过滤）** 候选只在**类型兼容**时存在：`stmt` 节点只能进「语句槽」（那么/否则/循环体/顶层），
`bool` 只能进「条件槽」，`value` 只能进「数值槽」。不兼容的候选**不参与最近距离计算**（用户 Q7：视为取消）。

**规则 4（最近吸附）** 距离用**加权欧氏距离**，x 权重更高（这正是解决"if 下方到底是块内还是块后"的关键）：

```
score = |px - ax| * 1.0  +  |py - ay| * 0.35
```

x 权重 > y 权重 ⇒ 指针在同一列（缩进）时优先"同级插入"，缩进更深时优先"进槽"。

**规则 5（阈值）** 最小 `score > 64` ⇒ **不吸附、显示"取消放置"**（预览线隐藏）。

**规则 6（预览）** 命中候选后：
- `aiDropY = 锚点 y`（相对树内容坐标）⇒ 引擎用 `rectFrom` 把 `ai_drop` 垂直移过去并显示；
- 同时把该候选的**目标缩进**用一条竖向短标记表示（复用一个 `ai_drop_indent` deco，`rectFrom:{x}`）；
- 拖到某行**上半部** vs **下半部** 决定「之前/之后」：`py < top(i) + h/2` ⇒ 之前，否则之后。

**规则 7（放下）** 松开左键 ⇒
- 命中且类型兼容 ⇒ `ai-node-drop {node, parentAddr, slot, index}`（store 里插入 + 记录撤销栈 + 节流校验）；
- 未命中 ⇒ 什么都不做，显示一行 flash「这里放不了」。

### 4.4 拖动已有节点重排

用户未明说，按"我没提到的问题全按你建议"实现：**树的已有行同样可拖**，
落点算法与 §4.3 完全共用（候选过滤排除"拖到自己内部"的候选，避免成环）。

### 4.5 撤销 / 重做（R2）

| 项 | 决定 |
|---|---|
| 范围 | **只作用于本屏草稿**（蓝图），不进全局历史 |
| 记录时机 | 所有会改草稿的动作：追加 / 删除 / 拖放 / 重排 / 改参数 / 套用模板 |
| 不记录 | 选中、折叠、缩放、平移、校验、保存（保存只清 `dirty`） |
| 容量 | 30 步（FIFO 丢弃最旧） |
| 实现 | `aiEditor.history: [blueprint…]`、`aiEditor.future: [blueprint…]`，深拷贝 |
| 快捷键 | `Ctrl/⌘+Z` 撤销、`Ctrl/⌘+Shift+Z` 重做 |

## 5. 引擎改动（"先改编辑器"）

| # | 能力 | 设计 | 为什么必须 |
|---|---|---|---|
| ① | **`stateKeys` 可声明** | `bundle.stateKeys: [...]`；`WHEN_KEYS` 校验改为 `DEFAULT ∪ 声明值`；布局台增加"状态键"输入 | 本屏要 12 个状态键，硬编码 3 个不够 |
| ② | **`rowsFrom`** | `{source, container, prototype, pitch, indentPx}`：把原型复制 N 份，每份 `x = base.x + indent×indentPx`、`w = base.w − indent×indentPx`、`text/label/action/payload/muted/disabled` 由行数据覆盖；返回 `contentH` 供滚动 | 树行与节点库行都是"按数据缩进的一列"，现有 `listFrom` 只能复制**单个固定 x 的按钮**且只认写死的 4 种数据源 |
| ③ | **`rectFrom`** | `rectFrom:{x?,y?,w?,h?}`，取 `sstate` 里的数值覆盖对应 rect 分量 | 插入预览线的 y、树的宽窄都必须由状态算 |
| ④ | **`kind:'input'`** | 文本输入：`{name, value, placeholder}` → `<input class="dl-input" data-field>`；`change` 时派发 `field.set` | AI 名称必须能改，现有 kind 只有 button/deco |
| ⑤ | **`pan`** | `pan:'both'` → 渲染出 `data-pan`，由 `app.js` 用"按下移动 ≥4px"映射到 `scrollLeft/Top`；同时**渲染前后保留滚动位置**（否则每次重渲染滚回顶部） | 自由平移视图；滚动保持是它的前提 |

**布局台同步**：右侧"元素·容器/滚动/网格"分区补 `rowsFrom` / `rectFrom` / `pan` / `kind:input` 的编辑控件；
舞台用 mock 行数据实时显示排布结果。

## 7. 与首版字符画的差异（记录，避免对不上）

| # | 首版 | 现在 | 原因 |
|---|---|---|---|
| R-1 | 树每行右侧放「选中/上移/下移/删除」 | 行内**不放按钮**；删除在参数栏 + `Del` 键，重排靠拖动 | 行模板复制带子按钮会让引擎复杂度爆炸；且拖放已覆盖重排 |
| R-2 | 参数区按 schema 生成任意多行 | **固定 3 选项槽 + 1 数值槽**，用 `when` 显隐 | 参数是异构表单，行模板表达不了"每行控件类型不同" |
| R-3 | 未提缩放实现 | 缩放 = **字号/行高/缩进**缩放，不是 `transform` | 滚动条正确；树里没有图片 |
| R-4 | 未提节点库布局 | 折叠分组（非选项卡），只显示 `owned>0` | 用户 Q1 + R7 |

## 8. 失败路径（按钮永不无声）

| 场景 | 表现 |
|---|---|
| 拖到不可插入处 | 预览线隐藏；松手 flash「这里放不了」；草稿不变 |
| 节点库存不足 | 库里该行置灰（不可拖）；参数栏底部提示「⚠ 节点不足：…（可先存草稿）」 |
| 校验未通过 | `ai_save` 置灰；校验回执逐条列出，点条目**滚动到并选中**该行（跨折叠自动展开） |
| 有未保存改动时返回列表 | 弹「确认丢弃」层（复用 `ed.confirm`） |
| 保存失败（服务端 4xx） | notice 显示服务端 `code` 文案，草稿保留 |
| 蓝图为空 | 树区显示「（空蓝图：套用下方模板，或左侧点节点加入）」 |

## 10. 实现偏离（务实取舍，逐条记账）

| 规格原写法 | 实际实现 | 为什么 |
|---|---|---|
| `repeatFrom`（**模板组**复制） | **`rowsFrom` + `rowRects()`**（复制**单元素**行，按数据缩进） | 行内不再放按钮（§7 R-1），所以不需要"组复制"；单元素行已足够，且引擎改动小一个量级 |
| `scale`（容器 `transform: scale`） | **按 `zoom` 放大 行高 / 缩进 / 字号** | `transform` 后浏览器不知道内容真实尺寸 ⇒ **滚动条算错、到不了底**；树里是纯文字，字号缩放不失真 |
| `rectFrom` 用于"树宽窄 + 预览线 y" | 同（已实现） | — |
| `stateKeys` 写死在引擎键表 | 布局表 `stateKeys` 声明 + `format.setLayout` 注册 | 让"哪些键有意义"归布局表，而不是引擎源码 |
| 参数区"按 schema 生成任意多行" | **固定 3 选项槽 + 1 数值槽**（`when` 显隐） | 参数是异构表单，行模板表达不了"每行控件类型不同"（§7 R-2） |

> 另：`kind:'input'` 实现时**顺带加了 `textarea`** —— 导入 JSON 需要多行输入，单行框粘贴长 JSON 不可用。
