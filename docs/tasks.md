# Debug-Lite v3 构建任务清单

> 用途：指导「完整框架」从零到可玩的主干开发。任务按阶段排序，含交付物、要点与验收标准。
> 设计依据：`docs/v3-design.md`（主文档）、`docs/items-data.md`（数值）、`docs/systems/*`（各系统细节）。
> 状态图例：`[ ]` 未开始　`[~]` 进行中　`[x]` 已完成　`[!]` 阻塞

---

## 0. 全局约定（所有任务必须遵守）

- **确定性**：引擎内禁止 `Math.random`；随机统一走 `rng.js`（种子 + 每 tick 派生子种子），同种子战斗轨迹必须完全一致。
- **纯函数引擎**：`engine.step()` 不碰 IO；输入 state + 双方行动，输出新 state + 状态差异。
- **AI 安全**：AI 程序是 JSON AST，服务端沙箱解释，禁 `eval`；单 tick 限步数。
- **美术/音乐**：不使用 v2 资源；像素占位，将来换图片素材；音乐暂不实现。
- **控制效果顺序**：持续效果 → AI 决策 → 控制效果复写 AI 行动。
- **超时扣血**：48 tick 起每 tick 扣血量上限的 6.25%（向上取整），保证 64 tick 前结束。

## P1 核心引擎（最关键）

### 基础设施
- [ ] **P1-1** `server/core/rng.js`：mulberry32 + 每 tick 子种子派生 + 状态可序列化
- [ ] **P1-2** `server/core/field.js`：坐标 clamp、基地位置、初始位置（x=3/x=12）、基地受击判定

### 数据表
- [ ] **P1-3** `server/data/qualities.json`：五品质（系数区间、角色/技能插槽数、点数、档位）
- [ ] **P1-4** `server/data/role-templates.json`：11 种模板（均衡/特化×5/专家×5，含 `highStat`、`pluginPoints`、`slotWeights`）
- [ ] **P1-5** `server/data/skill-templates.json`：参考 legacy 的 9 个技能模板（4 类型）
- [ ] **P1-6** `server/data/plugins.json`：角色插件（五维槽/特殊槽）+ 技能插件（基础/特殊槽），含档位点数/消耗
- [ ] **P1-7** `server/data/items-config.json`：掉落概率、类别权重
- [ ] **P1-8** `server/data/unlock.json`：段位解锁表

### 系统模块
- [ ] **P1-9** `server/core/items.js`：品质/插槽数/属性随机、档位、开箱、词条应用、仓库/组装/拆卸、点数校验
- [ ] **P1-10** `server/core/roles.js`：模板实例化（类型修饰：最高属性固定 + 其余随机）、装配插件、最终面板
- [ ] **P1-11** `server/core/skills.js`：实例化、插件叠加（基础/特殊）、`canCast`、四类型释放指令
- [ ] **P1-12** `server/core/effects.js`：持续效果结算、控制效果（AI 返回行动后复写）、到期移除
- [ ] **P1-13** `server/core/bullets.js`：生成/推进/等级碰撞/命中与消失（由近到远，阻挡→命中→射程）
- [ ] **P1-14** `server/core/unlock.js`：段位门控查询与过滤
- [ ] **P1-15** `server/core/engine.js`：
  - [ ] `createBattle`（初始化双方 + AI 上下文 + 基地）
  - [ ] `step()`（7 步 tick 循环，顺序：持续效果 → AI → 控制复写 → 同时行动 → 弹幕/角色碰撞 → 资源恢复 → 结束判定 → 输出差异）
  - [ ] 伤害管线（闪避 → 基础伤害 → 背击×1.5 → 暴击×1.5 可叠加 → 吸血 → 附加效果）
  - [ ] 结束判定（基地≤0 → 角色≤0 → 48 tick 起 6.25% 向上取整，64 tick 前必结束）
  - [ ] 状态差异输出（位移/朝向/资源/buff 粒子/弹幕路径/**碰撞格**/基地/事件/AI 轨迹）
  - [ ] `runFull()` 快进（与逐 tick 结果一致）

### 验证
- [ ] **P1-16** 硬编码 AI 跑通整场（48→64 tick 路径）
- [ ] **P1-17** 单元测试：行动、弹幕碰撞矩阵、效果结算、结束三路径、伤害管线（背击/暴击）
- [ ] **P1-18** 种子复现测试：同种子两场轨迹完全一致
- [ ] **P1-19** 快进 vs 逐 tick 一致性测试

**验收**：`npm test` 全绿；命令行可跑一场完整战斗并打印逐 tick 差异。

## P2 AI 系统

- [ ] **P2-1** `server/ai/ast.js`：节点 schema（literal/get/bullets/var/set/getVar/arith/cmp/logic/random/if/loop/break/function/call/action/seq）
- [ ] **P2-2** `server/ai/ast.js`：静态校验（白名单、字段、深度）+ **合法性检测**（程序必有可达 action；每个循环体必须有 action）+ 段位门控
- [ ] **P2-3** `server/ai/runtime.js`：续执行解释器（跑出一个行动即挂起、下一 tick 从断点继续）
- [ ] **P2-4** `server/ai/runtime.js`：局部变量跨 tick 持久、函数定义/调用、步数上限兜底
- [ ] **P2-5** `server/ai/runtime.js`：**执行轨迹 trace**（节点 id、条件真假、分支走向、最终行动）
- [ ] **P2-6** Blockly 集成（`public/js/editor/`），自定义积木覆盖全部节点
- [ ] **P2-7** 积木 ↔ AST 双向转换（编辑→AST 存盘；载入→积木还原）
- [ ] **P2-8** 编辑器按段位隐藏/禁用未解锁积木 + 实时合法性提示
- [ ] **P2-9** 端到端：编辑器 AI → 服务端解释器 → 打完一场

**验收**：能用积木拼出一个「有状态」AI（如变量记录模式），服务端执行正确，缺 action 的循环被拒绝。
