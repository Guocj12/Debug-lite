## 1. 隐式主循环（D-100）

**规则**：AI **不需要也不应**写外层循环；程序执行到最后一条语句后**自动回到第一行**。该结构在编辑器中显式可见且不可删除。

### A-1 跨 tick 持续产出

程序（隐含在 `while(true)` 中）：

```
body.s[0]  变量 n = 0
body.s[1]  若 n < 2 → { n = n + 1 ; 产出 move_right }
body.s[2]  否则    → { n = 0 ; 产出 skill1 }
```

| tick | 进入时的 `n` | 分支 | 产出 | 离开时的 `n` |
|---|---|---|---|---|
| 1 | 0 | `n<2` 成立 | `move_right` | 1 |
| 2 | 1 | 成立 | `move_right` | 2 |
| 3 | 2 | 不成立 | `skill1` | 0 |
| 4 | 0 | 成立 | `move_right` | 1 |

> **要点**：第 3 tick 结束后程序"跑完了"，但**不会停止**——回到第一行继续（`T-AF-9`）。这正是"有状态脚本"的语义基础。

## 2. 续执行与断点（D-104 / T-AF-3）

### A-2 断点必须落在 action 的下一条语句

```
body.s[0]  产出 skill1        ← 断点记录在 body.s[1]
body.s[1]  产出 defend        ← 断点记录在 body.s[2]
body.s[2]  产出 move_right    ← 断点记录在一个 pass 的末尾 → 下一 tick 从 s[0]
```

| tick | `frames` 栈顶 `childIndex` | 产出 | 说明 |
|---|---|---|---|
| 1 | 0 | `skill1` | 从入口开始 |
| 2 | 1 | `defend` | **从 s[1] 继续**（不是重跑） |
| 3 | 2 | `move_right` | — |
| 4 | 0 | `skill1` | pass 结束 → 隐式主循环回到 `s[0]` |

**等价性断言（T-AF-3）**：把程序一次性跑到第 n 个 `action` 的序列，必须等于"n 次 `resume` 的产出序列"。这是判断"实现是否真的在续执行"的唯一硬指标。

### A-3 循环计数跨 tick 保持

```
body.s[0]  循环(count=3) { 产出 move_left }     ← 合法：循环体含 action
```

| tick | 产出 | 帧内 `remaining` |
|---|---|---|
| 1 | `move_left` | 3→2 |
| 2 | `move_left` | 2→1 |
| 3 | `move_left` | 1→0 → 循环结束 |
| 4 | （循环已结束）→ 隐式主循环回到 s[0] → 新一轮 | 3 |

> 注意第 4 tick：循环结束后回到程序开头，于是**再进一次循环**（因为整个程序被隐式 `while(true)` 包着）。

### A-4 变量跨 tick 持久

`变量 cd1 = 0`；tick1 `cd1 = 2`；tick2/tick3 做 `cd1 -= 1` → tick4 时 `cd1 = 0`。
⇒ `vars` **不随 pass 结束而清空**（它属于 `AiContext`，不是局部帧）。

## 3. 函数（D-102 / D-103）

**语义**：函数 = 打包好的代码块，**无参数、无返回值**；但**有独立作用域 + 调用栈**（可读外层变量，内部 `var` 不泄漏）。

### A-5 作用域与调用栈

```
变量 全局 = 10
函数 f() {
    变量 局部 = 99
    若 全局 > 5 → 产出 skill1
    否则       → 产出 defend
}
body.s[1]  调用 f()
```

| 检查 | 期望 |
|---|---|
| `f` 内可读 `全局`（词法作用域链） | ✅ 读到 10 |
| `f` 内的 `局部` 在 `f` 返回后 | **不可见**（不泄漏到外层） |
| 调用时 `frames` 栈 | 压入 `fn:f` 帧；产出 action 时挂起，**断点位于函数内部**；下一 tick 从函数内继续 |
| 调用结束后 | 弹栈回到 `body.s[2]` |
| 递归 `f` 调用自己 65 层 | 超过深度上限 64 → 返回 `wait` + `ai.depth.limit`(**warn**) |
| 传参 `f(3)` / 返回值 `return x` | **校验期拒绝**（第一版不支持） |

## 4. 合法性检测（D-101）

### A-6 分支 action 规则（**每个分支都要有 action**）

| # | 程序片段 | 判定 | 原因 |
|---|---|---|---|
| A-6a | `循环 { 产出 skill1 }` | ✅ 合法 | 循环体有 action |
| A-6b | `循环 { 若 c → 产出 skill1 否则 → n = 1 }` | ❌ **拒绝** | `else` 分支**无 action** → 进入即永远产不出行动 |
| A-6c | `循环 { 若 c → 产出 skill1 否则 → 产出 defend }` | ✅ 合法 | 两个分支都有 |
| A-6d | `循环 { 若 c → { 循环 { 产出 skill1 } } 否则 → 产出 defend }` | ✅ 合法 | 嵌套循环体有 action |
| A-6e | `循环 { 若 c → 产出 skill1 }`（**无 else**） | ❌ **拒绝** | 隐式空 else 分支无 action |
| A-6f | `while(true) { 产出 move_right }` | ✅ **合法**（允许 `while(true)`） | 循环体含 action |
| A-6g | `循环 { break }` | ❌ 拒绝 | 该循环体无 action |
| A-6h | 函数体内循环缺 action | ❌ 拒绝（同上，逐层检查） | — |

**错误输出**：`{code:'ai_invalid', details:[{path:'body.s[1].then.body.s[0].else', code:'branch_without_action', message:'…'}]}`
⇒ **必须带 `path`**，供编辑器高亮具体积木（`T-AF-5/10`）。

## 5. 随机（D-90/D-91）

### A-7 每 tick 每用途各派生一条流

| # | 场景 | 期望 |
|---|---|---|
| A-7a | 同 tick 内 AI 调 `random` 3 次、暴击判定 2 次 | AI 与暴击**各用各的流**（`hash(seed,tick,'ai')` / `'crit'`），互不平移 |
| A-7b | 某个 AI 程序改成**多调 10 次** `random` | **暴击/闪避的随机序列完全不变** → 战斗其余部分不受影响 |
| A-7c | 挂起（产出 action）时 | **不消耗**任何随机 |
| A-7d | 未走到的分支里的 `random` | **不消耗** |
| A-7e | 同 seed + 同程序 | 行动序列与 trace **逐条一致**（`T-AF-2`） |

## 7. 兜底与错误（D-81）

| # | 场景 | 期望行为 | 日志 |
|---|---|---|---|
| A-9a | 单 tick 步数 > 10000 | 返回 **`wait`** + **重置到入口** + 继续战斗 | `ai.step.limit`(**warn**){steps:10000} |

## 8. 程序规范化与版本

| # | 场景 | 期望 |
