## 开发顺序（严格按此顺序）

### 第1步：后端基础 — server 目录
参照 `docs/05-战斗引擎.md` 和 `docs/02-通信协议.md`

需要创建的文件：
```
server/
├── package.json          # npm init，依赖 express + socket.io
├── index.js              # 主入口：Express 静态文件服务 + Socket.IO 事件路由
├── game/
│   ├── Player.js         # 玩家类（参照文档中的模型）
│   ├── BattleEngine.js   # 战斗引擎（核心逻辑，参照文档中的伪代码）
│   ├── RoomManager.js    # 房间管理
│   └── Timer.js          # 计时器
└── data/
    ├── skills.json       # 技能配置（参照 docs/03-数据配置格式.md 第一节）
    ├── characters.json   # 角色配置（参照 docs/03-数据配置格式.md 第二节）
    └── pixelSprites.json # 像素画配置（参照 docs/03-数据配置格式.md 第三节）
```

**实现要点**：
- index.js 处理所有 Socket.IO 事件（参照通信协议文档）
- 房间号用 4 位大写字母数字随机生成
- 服务端存储所有房间和玩家状态在内存中（Map 对象）
- 准备阶段 60 秒倒计时，超时自动以当前队列锁定
- 队列长度双方必须相同（取较短的为准，自动截断）

### 第2步：前端基础 — public 目录
参照 `docs/04-像素渲染与特效.md` 和 `docs/01-项目总览.md`

需要创建的文件：
```
public/
├── index.html             # 单页：div容器 + canvas + 各种UI面板
├── css/
│   ├── main.css           # 霓虹暗色主题 + 像素字体风格
│   └── mobile.css         # 响应式，适配手机竖屏
├── js/
│   ├── app.js             # 主入口：初始化socket连接，管理面板切换
│   ├── socket.js          # Socket.IO 客户端（CDN加载socket.io.js）
│   ├── ui/
│   │   ├── LobbyUI.js     # 大厅：创建/加入房间按钮 + 房间号显示
│   │   ├── PrepareUI.js   # 准备阶段：行动队列编辑器（核心交互！）
│   │   ├── BattleUI.js    # 战斗阶段：Canvas + 动画播放
│   │   ├── SkillSelectUI.js # 技能选择面板
│   │   └── PixelRenderer.js # 像素渲染总调度（参照文档第四节）
│   ├── game/
│   │   ├── ActionQueue.js # 行动队列数据结构 + 编辑逻辑
│   │   └── BattleAnimator.js # 战斗动画播放器
│   └── utils/
│       └── PixelDrawer.js # 像素绘图工具函数
└── data/                  # 可先从服务端通过 API 加载，或直接复制
    ├── skills.json
    ├── characters.json
    └── pixelSprites.json
```

**实现要点**：
- 使用 CDN 加载 socket.io 客户端：`<script src="https://cdn.socket.io/4.7.4/socket.io.min.js"></script>`
- 不使用任何前端框架，纯原生 JS
- 所有交互通过点击/触摸完成，不依赖键盘
- Canvas 绘制全部画面，不加载任何图片

### 第3步：核心交互实现

#### 3.1 大厅 (LobbyUI.js)
- 输入昵称 → 点击"创建房间" → 显示 4 位房间号 → 等待对手
- 输入昵称 + 房间号 → 点击"加入房间" → 进入等待

#### 3.2 技能选择 (SkillSelectUI.js)
- 双方就位后弹出技能选择面板
- 显示所有可用技能（从 skills.json 加载）
- 最多选 maxSkillSlots 个（默认3个）
- 确认后等待对方

#### 3.3 准备阶段 (PrepareUI.js) — 最重要！
- 顶部显示倒计时（60秒）
- 底部是行动队列编辑器
- 界面布局：
  ```
  [计时器]  [对方队列:已确认 ✓]  [你的队列:编辑中...]
  
  ┌─────────────────────────────────────────┐
  │          你的行动队列（可拖拽排序）        │
  │  [右→] [防御🛡] [攻击⚔] [火球🔥] [左←] │  ← 每个是彩色按钮
  │  [添加] [删除选中] [清空全部] [确认锁定] │
  └─────────────────────────────────────────┘
  
  行动按钮面板：
  [←左移] [→右移] [↑上移] [↓下移]
  [攻击⚔] [防御🛡]
  [技能1: 火球🔥] [技能2: 盾击🛡] [技能3: 疾步💨]
  ```
- 点击行动按钮 → 添加到队列末尾
- 点击队列中的项 → 选中高亮，可删除
- 队列按钮颜色对应行动类型：
  - 移动：蓝色霓虹
  - 攻击：红色霓虹
  - 防御：青色霓虹
  - 技能：金色霓虹
- 每次修改自动通过 socket 发送 update_queue
- "确认锁定"后不可再修改
- 双方都确认或时间到 → 进入战斗阶段

#### 3.4 战斗阶段 (BattleUI.js)
- 上方显示双方 HP 条（霓虹发光效果）
- 中间是 Canvas 战场
- 收到 battle_action 事件 → 播放对应动画
- 动画播放节奏：
  - 先显示行动名称文字（如"🔥火焰弹！"）
  - 移动角色到新位置（平滑过渡 300ms）
  - 播放技能/攻击特效
  - 显示伤害数字（飘字）
  - HP 条动画更新
  - 等待 600ms → 下一步
- 回合结束 → 显示回合结果 → 回到准备阶段

#### 3.5 像素渲染引擎 (PixelRenderer.js + PixelDrawer.js)
- 参照 `docs/04-像素渲染与特效.md`
- 从 pixelSprites.json 读取像素数据
- 按字符映射颜色渲染
- 实现霓虹发光效果
- 实现扫描线叠加
- 实现粒子系统

## 关键约束

1. ⚠️ **不要使用任何图片素材**，所有画面用 Canvas 绘制像素
2. ⚠️ **不要依赖键盘**，所有操作通过点击完成
3. ⚠️ **对手队列内容不能暴露**，只能显示长度和确认状态
4. ⚠️ **战斗逻辑全部在服务端**，客户端只渲染结果
5. ⚠️ **不使用任何前端框架**（React/Vue 等），纯原生 HTML/CSS/JS
6. ⚠️ **不使用数据库**，所有状态在内存中
